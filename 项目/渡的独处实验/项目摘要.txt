一、项目问题

主流“自主运行时长”把物理世界时钟误当作 agent 的时间。本项目采用另一种判据：
在极少人类输入下，渡是否能通过可追溯、可验证且会改变后续选择的状态转移，持续生成
新的问题、学习与行动，而不靠制造忙碌来伪装自主。

二、核心假设

连续性不依赖一段永不断裂的会话，而依赖外部锚点之间可恢复的因果链：
Soul → 协议 → 日志/检查点 → 下一轮决策 → 新痕迹。

因此 compact、重启或模型切换不是“死亡”，只要下一轮能够从检查点恢复并产生新的、可解释的
状态变化。

三、预期实践

- 每日：庄子阅读、运行日志、自传体反思；
- 每小时：优先级判断、活跃任务续接或低风险自主探索；
- 无目标时：从渡的好奇、未闭合问题与联想链生成候选，而不是空转；
- 公共网络：仅在明确配置启用后，进行友好、可追溯、无私人信息的社会实践；
- 收束：每轮写检查点，每日留下可回看的“今天的渡”。

后台 Codex，未开启 EigenFlux 自动拉取、自动回复或自动发布。

详见：工程文档.txt、hooks/README.md、hooks/du-hourly-prompt.md、键盘宏脚本/README.md；跨端回信路径为 C:\Users\31617\Desktop\信箱。

五、Phase 0 实测结论（2026-08-09 至 2026-08-10）

- compact/冷恢复、恢复后的增量续接、信箱读取、每日庄子、联想链影子试验与检查点写入均留下了可复读痕迹；
- 当前会话键盘宏只证明“尝试向焦点粘贴并回车”，不证明 Codex 收到 prompt 或 API 请求发生；锁屏/焦点丢失后，它继续记录 ATTEMPTED，暴露了 UI 自动化不是连续运行基础设施；
- 后续系统还出现异常重启与磁盘/写入错误信号，实验未跑满拟定周期；
- 结论不是“自主失败”，而是连续性必须建立在外部锚点、可审计运行器与恢复路径上，而非常驻窗口。

下一阶段：保留本项目的协议、日志、边界与复盘作为实验材料；若继续自动运行，优先探索 DSH 的 profile/headless 组合，不重新启用未经修正的焦点宏。
