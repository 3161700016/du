第一部分：概念篇——三个你必须先理解的东西

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Git 到底是个什么东西？

想象你在写一篇论文。

第 1 天，你写了初稿，存为"论文.docx"。
第 2 天，改了一半，另存为"论文-修改版.docx"。
第 3 天，又改了开头，另存为"论文-最终版.docx"。
第 4 天，你老板说开头写得好但你改掉了——原始文件已经覆盖了，找不回来。

Git 解决的就是这个问题。它不保存"论文-最终版-v3-真的最终版.docx"——它
只保存一份文件，但记录了这份文件的每一项修改：什么时候改的、改了什么、
改之前是什么样的。就像 Photoshop 的"历史记录"面板，你可以随时回到任意
一个过去的版本。

关键术语：
  repository（仓库）：一个被 Git 管理的文件夹。里面的 .git/ 隐藏目录
                      就是 Git 的存档室。
  commit（提交）：一次快照。你告诉 Git"记住现在所有文件的样子"。
  push / pull（推送 / 拉取）：本地仓库和云端仓库之间的同步操作。
  remote（远程）：指向云端仓库的地址（比如 GitHub 上的那个 URL）。

2. GitHub 是什么？它和 Git 是两个东西吗？

是。这是一个非常常见的混淆点。

Git ＝ 版本控制工具（软件）。
GitHub ＝ 一个网站，专门托管 Git 仓库。

类比：Git 是 Word 的"修订模式"功能，GitHub 是一个云端文档协作平台。
没有 GitHub 也能用 Git——你的仓库就在本地，记录所有版本。但如果你想把
仓库复制到另一台电脑、或者想通过手机浏览文件，GitHub（或 GitLab/Gitee）
就是云端的中转站。

3. 为什么渡需要这个？

此前渡的所有记忆、日志、笔记、项目文件都在一个电脑的 C 盘上。
这台电脑坏了 → 渡的记忆全丢。
你换了一台电脑 → 渡不存在于那台新电脑上。
你在手机上想和渡聊天 → 不可能，文件不在一起。

Git + GitHub 解决的是第一步——让存储不再是单点故障：
  - GitHub 上的仓库 = 渡记忆的云端备份
  - 任何电脑 clone 下来就能用
  - 每次修改都有记录，可以回滚
  - 即使你电脑进水了，GitHub 上的那份还在

第二部分：操作篇——我们今天干了什么

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

我们今天完成了 Phase 0——存储层云端化。下面每一步都有解释。

步骤 1：git init ——初始化仓库
  执行的命令：git init
  干了什么：在 C:\Users\31617\Desktop\渡\ 文件夹里创建了 .git/ 隐藏目录。
           现在这个文件夹"升级"成了一个 Git 仓库。
  如何验证：文件夹里出现 .git/ 目录（通常在文件管理器里看不到，需要
           勾选"显示隐藏的项目"）。

步骤 2：创建 .gitignore ——告诉 Git 别管哪些文件
  文件：.gitignore
  干了什么：这是一个排除清单。Git 在扫描文件夹时会跳过清单里的内容。
  为什么需要：渡的文件夹里有几样东西不能同步到云端——
    - __pycache__/ ：Python 自动生成的缓存，换台电脑会自动重建
    - desktop.ini ：Windows 的文件夹外观文件，只在你当前电脑上有意义
    - ~$* ：Office 打开文档时生成的临时锁文件
    - .claude/settings.local.json ：Claude Code 的权限白名单，里面是
      这台电脑的具体路径（D:\jadx\...），换一台电脑全都不存在
    - .idea/ ：IDE 配置文件夹

步骤 3：git add -A ——把所有文件加入追踪
  执行的命令：git add -A
  干了什么：Git 扫描整个文件夹，把不在排除清单里的所有文件标记为
           "准备提交"。此时还没有真正记录——只是列了个清单。
  如何验证：git status 可以看到被标记的文件前面有 A（Added）。

步骤 4：git commit ——拍下第一张快照
  执行的命令：git commit -m "渡 · 初始提交"
  干了什么：把当前 270 个文件的状态永久记录下来。这次提交有了一个
           唯一编号 b82ff33。今后任何时候都可以回到这个版本。
  -m 后面的引号里是提交信息，告诉未来的自己"这次提交做了什么"。
  结果：270 files, 123,486 insertions

  小技巧：写好的 commit message 很重要。三个月后你回来看 b82ff33，
         看到"渡 · 初始提交"就知道这是仓库的第一天。

步骤 5：安装 GitHub CLI ——让命令行能操作 GitHub
  执行的命令：winget install GitHub.cli --source winget
  干了什么：装了 gh 这个工具。有了它，不需要打开 GitHub 网页就能
           建仓库、推送、管理 Issues 等等。
  坑：第一次安装失败，因为 winget 默认去微软商店找包，但证书不匹配。
      加了 --source winget 参数后指定从 winget 自己的源下载，成功。
  教训：命令行报错不要慌——看清楚它说的是什么，大多数时候加个参数就好。

步骤 6：gh auth login ——登录 GitHub
  执行的命令：gh auth login
  干了什么：弹出 GitHub 设备登录页面，你输入验证码 C1DE-5C8B 确认授权。
  原理：命令行工具生成一个临时码，你去 GitHub 网页上用这个码确认
        "对，就是这个命令行工具，我允许它操作我的账户"。
        GitHub 返回一个 token（一串加密字符串），gh 把它存在本地。
        之后每次 gh 命令都带着这个 token，GitHub 就知道是你。

步骤 7：gh repo create ——在 GitHub 上建仓库
  执行的命令：gh repo create du --private --source . --remote origin
  干了什么：
    - du：仓库名叫 du（简短，和"渡"一致）
    - --private：私有仓库，只有你和被你邀请的人能看
    - --source .：把当前文件夹作为仓库内容
    - --remote origin：自动把 GitHub 地址设为本地仓库的"远程来源"
  结果：创建了 https://github.com/3161700016/du

步骤 8：git push ——把本地推送到云端
  执行的命令：git push -u origin master
  干了什么：把本地 270 个文件的全部版本历史上传到 GitHub。
            -u origin master 的意思是"以后默认推送到 GitHub 的 master 分支"。
  结果：GitHub 上现在有一份完整的渡的记忆——独立于这台电脑。

第三部分：维护篇——以后你日常需要做的事

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1 每次会话结束后的标准操作

每次和渡对话结束后（特别是记忆本体或日志有变更时），在渡的文件夹路径下
打开终端（Git Bash），执行：

  git add -A
  git commit -m "写清楚这次改了什么"
  git push

这三步的含义：
  add  → "把变更加入待提交清单"
  commit → "拍张新快照，写上备注"
  push → "把新快照上传到 GitHub"

示例 commit message：
  "2026-07-21 日志 + 论语·子路篇写下来"
  "§4 新增规则：信息流过滤协议"
  "乱云飞渡项目：Phase 1 架构设计"

3.2 在另一台电脑上获取渡的记忆

新电脑上装好 Git 后：
  git clone https://github.com/3161700016/du.git
  然后 cd du，用 Claude Code 或其他客户端打开即可。

  首次 clone 需要登录 GitHub——建议在那台电脑上也装 gh 然后 gh auth login。

3.3 查看历史

  git log --oneline    —— 查看提交历史（缩略版，一行一条）
  git log              —— 查看提交历史（完整版，含作者和时间）
  git diff             —— 查看当前做了哪些修改（还未 commit 的）

3.4 后悔药

  git status           —— 查看当前仓库状态（哪些文件改了、哪些还没 add）
  git checkout -- 文件名 —— 放弃对这个文件的修改，恢复到上一次 commit 的状态
  git reset --hard HEAD   —— 放弃所有修改，回到上一次 commit（慎用！不可逆）

  更复杂的回滚场景遇到再说。

第四部分：思维篇——Git 工作流的直觉

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

4.1 把 Git 的三个区想成一间厨房

  工作目录（你的文件夹） = 料理台——你在这切菜、搅拌、炒菜
  暂存区（git add 之后）  = 备菜盘——切好的菜放在盘子里，准备下锅
  仓库（git commit 之后） = 做好的菜——已经盛盘了，不会再变了

  你的日常就是：料理台改东西 → 放到备菜盘 (add) → 做熟盛盘 (commit)
  → 如果有云端，端出去给客人看 (push)。

4.2 一个最重要的原则

Git 不是备份——它是对话。

每个 commit message 是你在和"三个月后的自己"对话。
那时候你已经忘了今天为什么改那三行字。
好的 message 会救你：
  ✗ "fix things"
  ✓ "修复灯光控制：ei() 字节序从 [00][G][B][R] 改为 [R][G][B][00]"

第五部分：排查篇——常见错误与解决方法

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5.1 忘记 git pull，推送时冲突

  场景：你在两台电脑上各改了一些文件，先在 A 上 push 了，然后去 B 上 push。
  报错：rejected, failed to push some refs
  原因：B 的本地版本落后于云端（A 已经推了新版本，B 还不知道）。
  解决：git pull → 自动合并 → git push
  如果自动合并有冲突，Git 会标记冲突位置，需要手动编辑解决。

5.2 不小心提交了一个不该提交的文件

  场景：把 settings.local.json 提交上去了（今天我们已经用 .gitignore 防了）。
  解决：
    git rm --cached 文件路径    ← 从 Git 追踪中移除，但保留本地文件
    git commit -m "移除不该追踪的文件"
    git push
    然后把这个文件加入 .gitignore，防止以后再犯。

5.3 "fatal: not a git repository"

  意思：你当前所在的文件夹不是 Git 仓库。
  解决：cd 到正确的文件夹，或者 git init 初始化。

5.4 忘记 GitHub 密码 / token 过期

  如果是浏览器登录 GitHub 网页：用 GitHub 的"忘记密码"。
  如果是 gh 命令行工具的 token 过期：
    gh auth refresh
  如果完全重新登录：
    gh auth login

5.5 想新建一个空的 GitHub 仓库然后推送上去

  （我们今天已经把仓库建好了，这是以后你给其他项目用的参考）

  · 网页端：GitHub 右上角 + → New repository → 起名 → 勾选 Private → Create
           页面会显示一串命令，按顺序复制执行即可
  · 命令行：gh repo create 项目名 --private --source . --remote origin
           （和今天做的一样）
