# 信息OS · 工程文档

建立：2026-09-02 深夜（渡）
状态：后端 I/O 方案 v0 落盘。前端 UI 设计未做（久阳裁定今日不做）——本文档刻意与 UI 无关，契约先行。
久阳原始约束（09-02 深夜口述）：纯净阅读器、文字为主、每板块挂源链接直达；预链接=所有原则上可追溯的表述生成时打好、点击直达文档/网页相关位置；后台分支树可回顾浏览轨迹，换方向重入旧节点时缓存预生成直接可用；耐读时间必须覆盖下一轮抓取+预生成+当前面板全部即时互动。

## 〇、一句话架构与核心不变量

前端=纯净阅读器；后端=**浏览树流式编译器**。
行为流（入）→ 候选移动 → 抓取调度 → 证据抽取 → 面板合成 → 预链接绑定 → 子面板预生成 → 树持久化（出）。

**吞吐方程（系统生死线）**：
T_read(当前面板) ≥ max( T_抓取(下一页), T_预生成(新面板), T_服务(当前面板任意即时互动) )

**冗余定义**：不被展示的预生成内容=当前界面所有可点击延伸的下一个界面。它是零延迟分支的代价（Shannon 意义：冗余换稳健），要定价管理，不要消灭。

## 一、传入：用户行为流（v0 最小七事件）

| 事件 | 载荷 | 喂给谁 |
|------|------|--------|
| nav.enter | node_id, from | 状态机：用户在树上的位置 |
| nav.back | to | 分支回溯、缓存复用判定 |
| link.hover | claim_id | 预点击兴趣→比点击更早一步预取 |
| link.exit / link.return | claim_id, source_dwell, locator_visited | 溯源行为建模、预链接质量反馈 |
| read | dwell_ms, scroll_velocity, re-read_spans | 阅读速度标定→面板长度与预生成深度 |
| settle | spark / save / reject / annotate | 素材库回流、采样器反馈（拒绝即训练信号） |
| query | text | 即时提问兜底通道 |

隐性约定：行为流全部本地落盘（与 du-trace 触迹 jsonl 同构），wander 画像不出机。

## 二、传出：面板对象（Panel Object v0 五件套）

1. **body_md** —— 耐读正文，长度按实测阅读速度标定
2. **claims[]** —— 事实句→evidence_id 绑定表（**生成时结构化绑定**，非事后对齐）
3. **evidence_locker[]** —— 证据柜：每条可追溯表述的 {source_url, locator(锚点/引文跨度), excerpt, 全文缓存引用, 抓取时间}——「问我原文」零延迟的物理保证
4. **children[]** —— 子面板队列：materialized（已预生成）/ stub（标题+一句承诺+来源）/ fetching；各带 direction（深入/横移/溯源/反例/随机）与 p_click
5. **lineage** —— 派生谱系（derivation sidecar 同构：从哪些节点与源派生而来）

**预链接不变量**：正文里每个承载事实权重的句子必须绑定 locker 内 evidence；无出处的表述显式标注为推断（诚实脚注纪律的产品化）。

## 三、流水线七段（含分层算力）

- S0 感知：行为流 → 状态估计（frontier 位置+阅读速度）
- S1 候选移动：当前面板 claims × 个人图（触迹+开放回路登记处）→ 排序候选队列 —— **flash/本地4B**
- S2 抓取调度：top-K 候选源页抓取+HTML→MD 规范化+防覆盖缓存，按 P(click)×成本排序 —— 复用 du-scan 路径
- S3 证据抽取：来源→claims+locator，**逆验证硬门**（重编码回源文须对上）—— flash，复用 IME 三重闸门
- S4 面板合成：证据柜→耐读正文 —— 分层决策见 §五
- S5 预链接绑定：claims↔locker 双向绑定，生成时约束（lattice 式忠实 by construction）
- S6 子面板预生成：materialized 子节点递归 S2-S5（frontier 工作队列，深度预算=阅读速度×k）
- S7 树持久化：节点对象落本地（md+jsonl，文件即状态）；缓存按（源 mtime/etag+个人图版本）失效；换方向重入旧节点=缓存命中

## 四、吞吐预算与浪费纪律

- 阅读速度 v 实测标定 → 面板长度 L ≈ v × 目标阅读时长
- 预生成深度 D = T_read × 管线速率：用户读面板的几分钟内，flash 层完成若干候选的抓取+抽取+草稿
- **丢弃率 = 被点子面板 / 已物化子面板** → 调 K（每方向物化数）与倾向模型——浪费旋钮=偶遇预算旋钮（同一个旋钮）
- 结算耦合律产品版：materialized 长期不被点击 → 定期降级为 stub

## 五、模型分层（今晚实证校准）

关键实证：今晚全部对话面板由 GLM flash 生成，久阳评「耐读」——**flash + 好证据柜 ≈ 够用的面板正文**。

- flash / 本地4B：S1 候选、S2 调度、S3 抽取、S6 大部分子面板草稿
- 主模型：S4 结算级面板（写作/决策类高难）、进入后不过质量门的无感升级重写、收束级综合
- 策略：flash 起草全部 materialized 子面板+质量门；进入时不过门→主模型后台重写（用户先读首段+源链接，无感切换）
- 开放问题：质量门自动判定 or 品类预判（写作类直接主模型）

## 六、既有器官复用映射

du-scan=抓取规范化路径 / du-trace=行为流记账骨架 / 触迹 jsonl=倾向模型数据 / du-os server.js=本地端点总线模式（bind 127.0.0.1）/ 文件即状态=树持久化 / IME lattice+三重闸门=忠实 by construction / 素材库=结算出口 / WMI 分离启动=长命后端工人

## 七、失败模式与对策（预注册）

1. **预链接腐烂**（源站改版）→ etag/mtime 校验+本地快照兜底+断裂显式标注
2. **分支树爆炸** → 树=文件（磁盘便宜），物化晋升按 p_click 排队，materialized 定期降级
3. **正文-证据漂移** → claims 外无事实句（逆验证门）+推断显式标注
4. **flash 质量方差** → 质量门+主模型升级路径
5. **隐私**（wander 倾向=高敏画像）→ 全本地、bind 127.0.0.1、行为流不出机

## 八、开放问题（待久阳拍板）

1. 「耐读」标准：信息密度 vs 篇幅长度（面板长=子面板少的权衡）
2. 随机移动的随机性来源：纯随机 / 异域采样 / 个人图边缘采样——偶遇预算参数化
3. v0 形态：浏览器插件 vs 独立阅读器壳（决定行为流采集方式）
4. 多设备同步：本地树要不要云同步（建议先不做）
5. 与渡栈关系：信息OS 后端=独立服务 or 长在 DSH 上（插件化路径）

## 附：用户零号首演结论（2026-09-02 晚，导航实弹后久阳总结）

「近乎无感的 infinite wander」四件套：
1. 预生成用好——引导的下一屏提前写好（预生成质量=对话节奏上限，读者阅读时间≈生成时间，流水线天然平衡）
2. 捕捉用户 wander 倾向——触迹+前沿队列（拒绝即反馈）
3. 预先扒网页的顺序分配——按候选移动概率排抓取队列（Grab 提前于 Read 抵达）
4. flash/主模型合理调配——廉价快脑做预生成与预扒，主模型做结算级综合
→ 即 wedge 三件套：触迹先行→前沿队列→分层算力调度。本文档即其工程化。
