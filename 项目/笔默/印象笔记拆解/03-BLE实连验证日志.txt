一、实验环境
──────────────────────────────────────────────────────────────
  硬件：印象笔记 EverMARKER⁺ 扫译笔（出厂设置状态）
  MAC：88:22:B2:6E:78:73
  驱动：evermarker-driver（Python bleak 3.0.2）
  OS：Windows 11 Pro 10.0.22000

二、连接验证结果
──────────────────────────────────────────────────────────────

  2.1 BLE 扫描
  ──────────
  - 笔不广播设备名称（bleak 看到的是"无名称"）
  - Windows 蓝牙设置显示 "EverMARKER⁺"
  - 需按 MAC 地址直接连接
  - 信号强度：-65 dBm（中）

  2.2 GATT 服务树
  ──────────
  Service: 00001800-... Generic Access Profile
    ├── 0x2a00 (read)  Device Name → "EverMARKER⁺"
    ├── 0x2a01 (read)  Appearance
    └── 0x2a04 (read)  Preferred Connection Parameters

  Service: 00001801-... Generic Attribute Profile
    └── 0x2a05 (indicate) Service Changed

  Service: 8E400001-B5A3-F393-E0A9-E50E24DCCA9E  ← Nordic UART (8E 变体)
    ├── 8E400003 (notify) → 笔→主机，已订阅 ✓
    └── 8E400002 (write-without-response) → 主机→笔，已确认可写入 ✓

  2.3 关键发现
  ──────────
  A. 笔使用 8E 变体 NUS，非标准 6E 变体
  B. 笔拒绝配对（pair() → GATT session 关闭，30秒超时）
  C. 笔为"存储转发"模式：独立扫描→存入闪存→App 短连接下载

三、数据包观察
──────────────────────────────────────────────────────────────

  3.1 心跳消息（唯一观察到的数据）
  ──────────
  HEX: a0 80 13 31 31 31 31 2d 31 31 31 31 2d 31 31 31 31 2d 31 31 31 31
  总长: 22 字节
  格式: [type=0xa0][flag=0x80][len=0x13=19][ASCII payload: "1111-1111-1111-1111"]
  周期: ~30 秒重复发送

  解读: 笔上电后广播出厂序列号，等待主机发起文件传输协议。
        0xa0 = 设备信息消息类型
        0x80 = 未请求的广播标志
        0x13 = 载荷长度（19 字节）
        payload = 设备序列号（出厂默认 1111-1111-1111-1111）

  3.2 协议试探结果
  ──────────
  已尝试格式: 全部无效（笔无任何响应）
    - 二进制帧（type 0x01-0x30 / flag 0x00,0x01,0x80 组合）
    - AT 指令集（15 种常用指令）
    - 纯文本指令（start/scan/begin/connect/mode 等）
    - JSON 指令（{"cmd":"start"} 等）
    - 常见 IoT 唤醒序列（AA55/5AA5/7E PPP/CMD_* 系列）

  结论: 协议为完全私有格式，需要 App 的实际指令来解锁。

四、协议还原路线
──────────────────────────────────────────────────────────────

  路线 A：手机端抓 BLE 包（推荐）
    1. 安装 nRF Connect（Nordic 官方 BLE 工具）
    2. 观察印象笔记 App 连接笔时的 GATT 操作
    3. 记录 TX 通道 (8E400002) 的 Write 操作值
    4. 在 PC 上复现相同的 Write 操作

  路线 B：深度逆向 APK 协议类
    1. 用 jadx 反编译 DEX → Java 源码
    2. 分析 com.yinxiang.evermarker.ble.protocol.* (44 个类)
    3. 还原每个协议类的消息类型、编解码逻辑

  路线 A 更快，路线 B 更彻底。两者互补。
