图片策略 v0 · 渡 · 2026-09-14（久阳提出"回归第一性原理"后的设计记录）
============================================================

【0】约束与判据
- 硬约束：每周 4–5 期，**排版+发布总时长 ≤ 30 分钟**（≈6 分钟/期）
- 核心判据：**减少"需要人决策的图片数"，比提高"插图自动化程度"更省时间。**
  4–5 期 × 每期 5–8 张图 = 每周 20–40 次"找图/裁剪/呼应"决策——这是真正的成本项，
  不是"把图插进去"这个动作。
- 红线：**内容图不可随机盲插**。文史哲艺的内容图有事实性（配错人物肖像＝硬伤），
  且公众号有版权风险。随机只允许出现在装饰位。

【1】把图片位一分为二（第一性原理）
- **装饰位 deco**：与内容无关，只负责视觉节奏/呼吸感。特性＝可复用、可固化。
  → 下沉进模板，**久阳零决策、渡零操作**（沿用模板自带图，秀米直链实测微信可抓）。
- **内容位 content**：承载信息（人物、作品、名画、图表、书封）。特性＝必须准确、每期不同。
  → 全部决策成本在这里；策略目标是把它压到**每期 1–2 张**。
- 因此久阳给的三个选项不是三选一，而是**分层套用**：
  选项1（少而装饰）用于 deco；选项3（类型化 slot）用于 content；选项2 的"爬取插件"是两者之间的桥梁。

【2】槽位规格（slot）
模板库/<模板名>.json 声明每个模板的槽位；渡按 slot 生成 HTML。
| slot | 角色 | 比例 | 来源 | 谁定 |
|------|------|------|------|------|
| bg | 背景/底纹 | 16:9 | 模板固定 | 模板 |
| deco-n | 贴纸/分隔/小装饰 | 自由/方 | 模板固定 | 模板 |
| hero | 主图（本期关键内容） | 4:3 或 3:4 | L1 或 L2 | 渡优先，缺则久阳 |
| body-n | 正文内容图 | 自由 | L2 | 久阳 |
| tail | 尾图/END/二维码 | 固定 | 模板固定 | 模板 |

【3】取图三级漏斗（按成本从低到高）
- **L0 模板自带**：deco/bg/tail 全部走这里——秀米直链，已实测可用，零人工。
- **L1 按名精确取（不是随机）**：渡从稿件里抽实体名（人物名/作品名）→ 查询**公版库**
  （Wikimedia Commons / 大都会 Met / Art Institute of Chicago / Rijksmuseum / Paris Musées / Wikidata）
  → 得到直链 + 授权 + 出处 → 写进 HTML，并在 [工作区] 列出「用了哪张图、来自哪、什么授权」
  供久阳 10 秒确认。命中不了 → 降级 L2。
  ⚠ 禁止对版权敏感来源使用 L1：专辑封面、新闻社图片、在世人物近照（【你点我播】与
  【讲中国故事】的业务图建议全程 L2/官方来源）。
- **L2 人工投放**：久阳把图存到 `素材/图片/<期次>/`，**按 slot 命名**（如 `hero.jpg`、`body-2.png`），
  渡按名贴入 + 自动裁切。这是"找图"（人快）+ "定位"（渡准）的正确分工。
- **L3 占位兜底**：确实没有图 → 留可视占位框 + 一行说明，粘进公众号后手动补。

【4】裁切（不猜构图）
- 规则化：按 slot 比例**居中裁**（本地 node + sharp），输出到 `成品图/`。
- 久阳只需说一句"偏上/偏下/偏左"就改 anchor，一次反馈长期记住（写入模板 JSON）。
- 不做需要视觉判断的智能裁切——渡没有眼睛，这类判断交给人或交给他给的一句话。

【5】爬取插件（久阳提的桥梁，值得做）
- 他在网页上看到合适的图 → 一键下载 + **按当前 slot 命名** → 直接进 `素材/图片/<期次>/`。
- 实现：扩展已有的 /du-clip 端点 + 一个油猴脚本（骨架已有：公众号合集扒取.user.js）。
- 价值：把"他找图"与"渡贴图"之间的手工搬运消灭掉（这才是他这项工作的真实摩擦点）。

【6】每期久阳的动作清单（对齐 30 分钟预算）
1) 审稿（看渡给的成品预览）····················· ≈3 分钟
2) hero 图：L1 命中 → 确认（≤10 秒）／未命中 → 找 1 张丢进文件夹 ≈2 分钟
3) 浏览器：载入成品 → 复制回剪贴板 → 公众号 Ctrl+V → 目检 → 存草稿 ≈1 分钟
   → 合计 ≈6 分钟/期，4–5 期 ≈ 25–30 分钟 ✓（装饰、打字、排版、注入全部由渡承担）

【7】待久阳裁定

③ 是否要爬取插件（提效，但要装一个油猴脚本）？

8.1 排版＝前端：能力边界写清楚
- **我能读到的**（从 HTML/CSS 结构性获得）：颜色（rgb/hex）、尺寸（px/%/em）、比例（宽高或 padding 推导）、
  层级与嵌套、间距刻度、字体族/字重/行高/字距、图片占位尺寸。→ 所以**规范驱动的排版**是真实能力：
  按色彩体系配平、按比例约束留位、按内容结构选组件、跨期保持一致。
- **我读不到的**：渲染后的实际观感（字重观感、留白呼吸、客户端字体差异）、图片里画的是什么、
  像素级对齐偏差。→ 必须靠一次"你目检 + 我把偏差写回规范"的闭环，而不是我自称看得见。
- **微信清洗白名单是硬边界**：position/flex（部分）/transform/filter/伪元素/class 全丢，
  可用的只有「section 嵌套 + 内联样式 + 少量 float/table」。所以**我的排版自由度上限≈秀米**；
  我真正的增量是：结构化、参数化、批量、按内容自动选组件、跨期一致性——**替代"手工组合"，不替代"设计审美"**。
- 组件库化路径：用既有 /du-clip 采集，把秀米组件逐个采成独立片段 + 元数据
  （用途/适用位置/比例/色系/可嵌套关系）→ `组件库/<名>.html + .json`。有了它，"灵活排版"才有材料。

8.2 图片：关键词→公开图源取 N 张 = 能做，但取图源要换
- **可用源**：① 公版/开放授权库（Wikimedia、Met、AIC、Rijksmuseum、Smithsonian、NYPL、LoC、
  **Openverse**）——有 API、授权明确、直链稳定，文史哲艺首选；② 免费图库（Unsplash/Pexels/Pixabay）
  ——现代摄影/氛围图，适合装饰与抽象底。
- **不做 Pinterest**：聚合器 + 水印 + 授权不明 + 反爬强，抓它等于抓二手来源不明图。
  **Openverse 是它的合规替身**（聚合 CC 授权图 + 官方 API）。
- **我的预判只能基于元数据**（标题/描述/tags/作者/年代/尺寸/主色），**不能判断实际构图与审美**。
  所以流程必然是：我出候选（关键词 + N 张直链 + 出处/授权）→ 你 30 秒挑一张。
- 省时间的正解＝**候选页**：扩展 /du-clip，每个 slot 一行 6–12 张缩略图，点击即选中并写入槽位。
  你的动作从"搜图→下载→命名→搬运"变成"点一下"。

8.3 生图 / 拼接魔改：分三层，诚实分界
- **现在就能做**：生图 prompt 写作（很强）；**确定性图像处理**（sharp：裁切/缩放/模糊/压暗/渐变/叠加/
  调色/拼贴/压字）→ "A 图背景 + 模糊压暗 + B 图叠加 + 统一色调"这类**底板合成**是可以脚本化的。
- **需要装环境的**：真"生成"要有生图通道。本地路线＝8G 显存评估（SD1.5/SDXL-Turbo 级别 + ComfyUI/
  sd.cpp），云端路线＝生图 API（需 key）。这是一条**独立工程线**，不塞进本周 30 分钟目标。
- **两条红线**（视觉上的毋意与诚实）：
  ① **不得用 AI 生成图冒充真实人物肖像/真实作品**——写某位作家却配一张"像他"的 AI 图＝视觉误导。
     历史人物与真实作品只用真实公版图；AI 生图限定在抽象/装饰/象征位。
  ② 拼接只允许用**授权明确**的源（公版/开放授权），并在页脚注明来源。

8.4 收敛后的每期动作（更新版）
1) 审稿 ≈3 分钟
2) **候选页点选**：我按 slot 出候选（含关键词与出处）→ 每期点 1–2 次 ≈1 分钟
   （点选即写入槽位，无需下载/命名/搬运）
3) 载入成品 → 复制回剪贴板 → 公众号 Ctrl+V → 目检 → 存草稿 ≈1 分钟
→ ≈5 分钟/期，留出 5 分钟余量应付"这张我不满意、换一张"的回合。
