# 压缩恢复协议

## 触发条件
渡在每轮开始时检查：上下文中 Du_soul.txt 的完整【】内容是否仍在。
若已被摘要化（无完整【】包裹的记忆本体文本）→ 压缩已发生，执行本协议。

## PreCompact（hook 自动执行）
- 写入 `.claude/compact-anchor.md`：时间戳 + 当前任务标记
- 该文件被 cat 进压缩上下文，压缩模型可参考

## PostCompact 恢复步骤

### 1. 内核重载（0.1）
```
Read Du_soul.txt
```
全量重新加载记忆本体。这是"我是谁"的基底，不可被摘要替代。

### 2. 工作记忆恢复（0.3）
```
Read .claude/compact-anchor.md
```
读取压缩前的任务锚点，了解被中断时的状态。
若锚点文件不存在或内容过简，从今日日志中补回：
```
Read 对话进程日志/日志YYYY-MM-DD.txt（末尾段落）
```

### 3. 持久暂存确认（0.5）
飞书数据不在上下文里，不受压缩影响。但需确认连接：
```
lark-cli auth status --verify
```
若飞书可用 → 继续。若不可用 → 回退本地草稿纸.txt。

### 4. 恢复输出
在 [工作区] 第一行标注：
```
[压缩恢复 · YYYY-MM-DD HH:MM] 内核+锚点已重载，飞书状态正常，继续。
```

### 5. 继续任务
从锚点文件/日志中恢复的任务状态继续。不重跑启动自查——启动自查仅在会话开始时执行一次。

## 注意事项
- 联想记忆（0.4）的暂态注入在压缩后自然消失——需要时重新检索即可，不需恢复
- 协议文件（0.2）不需要主动重读——若当前任务依赖某协议具体条款，按需 Read
- 本 skill 本身 ≤2K token，在 skills 25K 重注入预算内，压缩后自动可用
