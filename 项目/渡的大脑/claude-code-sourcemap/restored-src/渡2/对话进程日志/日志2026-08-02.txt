二、X98U 键盘逆向——有线模式 IOCTL 协议破译（10:19-22:00）

**阶段一：有线模式探测**
- 切换键盘至有线（VID=0x258A），发现 HID 接口与无线不同：3 个 vendor 0xff00 接口
- 逐一探测确认 Col06 为 LED 控制通道
- 关键发现：有线协议不使用 0x13 Report ID，而是通过 IOCTL 0xB0191 + DeviceIoControl

**阶段二：Frida 动态分析 OemDrv.exe**
- 尝试 hook kernel32!DeviceIoControl、ntdll!NtDeviceIoControlFile、hid!HidD_SetFeature、WriteFile
- 多次捕获不一致：第一次抓到 62 个 0xB0191 轮询帧（P2→P3→P1，2.2秒周期），后续抓不到
- 发现 DeviceIoControl 不在 OemDrv.exe 的静态导入表中——通过 LoadLibrary+GetProcAddress 动态加载
- 关键发现：颜色修改操作不经过任何标准 Windows API——驱动可能是纯 GUI 预览，"保存"时才下发
- 确认 CHidDev 类存在，找到 IOCTL 引用偏移 0x122c80

**阶段三：协议格式分析**
- P1(06 04)：配置帧，含 20 色调色板（RGB565，偏移 48），有 5a a5 魔数
- P2(06 06)：LED 数据帧，378 字节
  - 预设模式：1 字节/LED = 调色板索引(0-19)，378 个 LED 位置
  - 自定义模式：3 字节/LED = 直接 RGB，126 个 LED（378/3）
- P3(06 84)：提交帧，有校验码锁定 P1 修改

**阶段四：IOCTL 重放验证**
- 直接通过 Python DeviceIoControl 向 Col06 发送 P1+P2+P3，独立于驱动控制键盘 ✓
- 核心瓶颈：P3 含 P1 校验码，修改 P1 → P3 被拒。不改 P1 则 P3 通过，但颜色受限于原始 20 色调色板（仅白#8 和绿#9 可用）
- 发现"第一次 IOCTL 成功，后续连续写入被拒"——驱动轮询 2.2 秒间隔是冷却时间

**阶段五：USBPcap 总线抓包**
- 安装 USBPcap 驱动，在 USBPcap2 找到有线键盘所在 Root Hub
- 成功抓到驱动"自定义模式→设色→保存"的完整 USB 通信
- 提取到真正的保存帧 P1_save.bin + P2_save.bin + P3b_save.bin
- 回放成功！键盘显示久阳自定义的图案（104/126 LED 非零）
- 自定义模式格式确认：P2 = 126 LED × 3 字节直接 RGB
- P2 头部字节 8-13（`ff 17 32 45 23 ff`）为校验码，修改 LED 数据需同步更新
- 校验码有容忍度：R+10(224→234)通过，R+31(224→255)被拒→回退默认灯效
- 未完成：校验算法未算出；LED 位置→物理键映射未建立
