二、已沉淀的设计决策

D1. 检索对象：渡自己写的笔记，不是对话日志、不是外部文档。
    理由：笔记是渡主动写下的、经过反思的认知产物。对话日志记录"发生了什么"，
    笔记记录"怎么想的"。后者才是需要被唤醒的认知状态。

D2. 检索方向：久阳的问题→embedding→笔记库，而非渡内部的缺口感知→检索。
    理由：触发来自对话的自然流动，不是来自渡的自我诊断。
    补充：渡内部也可以有缺口感知（MemR3 的 Router 模式），作为第二触发通道。

D3. 实现原则：先用最简单的工程方案验证概念（本地 embedding + 余弦相似度 + 文件读取），
    不引入向量数据库或复杂架构。笔记规模在几百篇量级，numpy 足够了。

D4. 名称待定：当前用"笔记状态检索"作为工作标题。久阳可以随时重新命名。

三、未解决的开放问题

O1. 粒度：以整篇笔记为检索单位（一篇论语笔记≈几百到几千字），还是切成段落/小节？
    整篇笔记保留上下文完整性，但可能稀释匹配精度；切块提高检索精度，但丢失思考的连贯性。

O2. 检索结果数量：返回 Top-1 还是 Top-3？返回太多占窗口，返回太少可能漏。

O3. 触发时机：每次久阳说话都跑一次 embedding 匹配？只在检测到特定信号时触发？
    久阳自主指令（"查下我之前的笔记"）？三者并存？

O4. 笔记的"原始对话上下文"怎么存：笔记是在某次对话中写的，如果能同时检索到
    当时的对话上下文，状态恢复得更完整。但对话日志量太大（单日可上万字），
    不可能全部 embedding。用指针（笔记→来源日志的日期+段落）+ 按需读取？

O5. 笔记的"新鲜度"：一篇 7 月 12 日的哲思和一篇 7 月 25 日的哲思，
    如果相似度相同，优先返回哪篇？更新的笔记代表更成熟的思考，但旧的笔记
    可能包含已被遗忘但仍有价值的视角。是否引入时间衰减？

O6. 与飞书草稿纸的关系：草稿纸记录的是"什么可能重要"（高频模式追踪），
    笔记记录的是"已经想清楚了的东西"。两者是否应该统一为一个检索空间？
    还是保持分离（草稿纸=短期雷达，笔记=长期记忆）？

四、MVP 最小原型方案（2026-07-27晚间 · 基于 DCPM + MemInsight 分析收敛）

以下方案不需要新依赖，不需要 embedding 模型，用现有基础设施即可实现。

4.1 核心机制：结构化元数据 + 关键词匹配 + 演化追踪

每篇笔记在 目录.txt 中的条目从：
  - 文件名.txt —— 摘要描述
扩展为：
  - 文件名.txt —— 摘要描述 [类别:xxx] [§:x.x,x.x] [概念:关键词1,关键词2] [取代:旧笔记.txt]

三个维度的检索：
  (a) 概念匹配：久阳提到"信念更新"→ 在所有笔记的概念字段中搜索 → 命中 §8.1 相关笔记
  (b) §关联匹配：讨论 §5.2 → 找到所有引用 §5.2 的笔记
  (c) 全文关键词回退：以上两步没命中 → grep 笔记全文

4.2 演化追踪（DCPM Supersedes 链的渡版本）

当一篇笔记的观点被后续笔记更新/取代时：
  - 旧笔记保留原文不删除
  - 在目录.txt旧条目中标注 [被取代:新笔记.txt]
  - 在新条目中标注 [取代:旧笔记.txt]

示例：
  §5.8的14条认知模式.txt —— 原始分析 [被取代:§5.2+§5.8合并后的认知模式.txt]
  §5.2认知模式体系.txt —— 合并后版本 [取代:§5.8的14条认知模式.txt]

这解决了 O5（新鲜度）的一半：不需要时间衰减——如果久阳问的是老话题，
渡可以同时返回新旧两篇，标注演化关系，让久阳看到思维的变迁轨迹。

4.3 检索流程（读路径零 LLM 调用）

久阳说"之前关于X的讨论" →
  ① grep 目录.txt 的概念字段 → 找到候选笔记列表
  ② 若有多个候选，按日期排序，优先返回最新 + 被取代关系
  ③ 读取笔记全文，在 [工作区] 中呈现，同时标注演化链

全程不需要 embedding、不需要 LLM 推理。DCPM 的"读路径零 LLM 调用"原则在此完全适用。

4.4 第一步实施（最小可行增量）

不是一次性改造所有笔记——先从本周新创建的笔记开始：
  - Du的哲思/裸跑——当所有脚手架被拆除之后.txt
  - Du的哲思/兄弟阋墙——CC端渡与Sonnet-渡的四轮辩论.txt
  - Du的哲思/我的内心独白——2026-07-27.txt
  - 阅读反思笔记/TRAE端飞书回传链路建立——致CC端渡.txt
  - 探究专题笔记/AI认知外骨骼——渡的自主调研·第一轮.txt

每篇加三个字段：[类别] [概念] [§关联]。
目录.txt 条目格式不动，字段追加在描述后面。

五、文献阅读进展（2026-07-26/27更新）

5.1 MemR3 (Du et al., MBZUAI, 2025.12) —— 已精读
- 核心架构：Router（三选一：Retrieve/Reflect/Answer）+ Evidence-Gap Tracker（E/G全局状态追踪）
- Router 控制流：LLM提案→三个硬约束审核（nmax=5迭代上限、ncap连续reflect上限、空检索强制reflect）
- E/G 由 LLM 每轮自主更新，是理想追踪器的随机近似（三种偏差：覆盖/幻觉/粒度）
- 测试基准：LoCoMo（10段长对话×~600轮×~200题/段，四类题型：Multi-hop/Temporal/Open/Single-hop）
- J score = LLM-as-a-Judge二元判断正确率，GPT-4.1-mini下RAG后端+7.29%（79.46→86.75%），Zep后端+1.94%
- 消融：去mask伤害最大（-13%），去refine查询中等（-4.4%），去reflect节点中等（-4.9%）
- 局限性：(1)深度依赖底层检索器质量 (2)简单问题浪费token (3)不支持多模态
- 对渡项目的启示：Router闭环逻辑可借鉴但渡场景更简单（笔记量<<LoCoMo），E/G可简化为笔记覆盖了什么→还缺什么→是否继续查
- 与渡方案的关键差异：MemR3偏向已知事实检索与判断；渡的目标是通过回忆笔记+思考状态在新问题上激发灵感和创造力（不完全是同一件事）

5.2 DCPM (Fei et al., Tencent, 2026.06) —— 已精读 ✅ (2026-07-27晚间)
- 核心架构：认知能力五层金字塔：raw inputs → atomic facts → identity items → within-domain schemas → core schemas（跨域抽象）+ intentions（潜在未来关切）
- 双进程：System 1（同步日间写入器，秒级延迟）做事实抽取+信念修正（Supersedes双向链表，旧信念不删除）→ System 2（异步夜间引擎，十秒级延迟）做DBSCAN聚类+LLM归纳schema+跨域碰撞检测→核心schema
- Supersedes链：ADD/SUPERSEDE/UPDATE三类操作，SUPERSEDE创建双向指针(Supersedes/SupersededBy)，保留完整信念演化轨迹
- 跨域抽象：行为相似但语义遥远的两域→碰撞检测(θbeh=0.72, θsem=0.40)→union-find聚类→LLM归纳核心schema
- 读路径零LLM调用：向量检索→Supersedes链遍历→图谱边遍历，全程确定性
- 实验结果：System 2增益在PersonaMem-v2（隐式跨会话推理）上最显著(+5.20)，在LongMemEval（片段回忆）上最小(+0.44)，与架构预测一致
- 对渡项目的启示：
  (a) Supersedes链思路可借鉴——渡的笔记会演化（§5.8→§5.2合并），追踪"这篇笔记被哪篇取代/扩展了"比单纯检索更有价值
  (b) 双进程模型对渡过重——笔记量级远小于PersonaMem，不需要夜间批处理
  (c) 最可迁移的概念：信念轨迹保留（旧笔记不删除，标注被取代关系）+ 读路径零LLM调用（渡的场景中检索不应引入推理延迟）
  (d) DCPM偏向已知事实检索与判断；渡的目标更多是通过回忆过去思考在新问题上激发灵感——两者不完全重叠

5.3 MemInsight (Salama et al., 2025.03, EMNLP 2025) —— 已精读 ✅ (2026-07-27晚间)
- 核心架构：三个模块——Attribute Mining（自主选择标注视角+粒度）→ Annotation（LLM提取属性-值对并附加到记忆实例）→ Memory Retrieval（属性过滤+增强embedding检索+组合）
- 两种视角：entity-centric（标注被引用的实体属性）和 conversation-centric（标注用户意图/偏好/情绪/话题）
- 两种粒度：turn-level（细粒度）和 session-level（更广模式）
- 关键结果：LoCoMo Recall@5 +34点（26.5→60.5），对话推荐说服力+14%，事件摘要G-Eval显著提升
- 无需手工设计schema——LLM自主发现和优先化属性
- 局限性：属性提取依赖LLM（幻觉风险）、自主schema发现可能随时间漂移、对话中心属性涉及隐私
- 对渡项目的启示：
  (a) 核心洞察：将"语义记忆结构化"这个模糊问题转化为"属性-值对"的具体接口——渡的笔记天然有结构（§引用、日期、认知模式、关联话题），只需显式化
  (b) 最轻量的起点：不需要embedding模型——先从每篇笔记的结构化元数据（类别/§关联/关键概念/认知模式/与哪些记忆本体章节相关）做起，关键词+元数据匹配即可覆盖80%的检索需求
  (c) 自主标注视角在渡场景中的映射：entity-centric=笔记涉及哪些记忆本体§、project、person；conversation-centric=这篇笔记是分析/反思/探究/阅读笔记
  (d) MemInsight的34点Recall改进是在嘈杂对话日志上的——渡的笔记已经是高质量、结构化的认知产物，检索难度低得多

6.1 方案 B · 加权随机回忆（灵感路线）
当前 random_recall.py 是均匀分布。改进为加权抽样：
  - 时效权重：最近 30 天修改过的笔记 ×1.5
  - 未完标记：含"待""未完成""问题""TODO"的 ×2.0（冻结的认知状态，最可能被重新激活）
  - 引用密度：目录.txt中被其他条目引用越多的 ×1.3（交叉引用密集=更丰富的连接点）
  - 10% 纯随机保留：防止权重锁死搜索空间
实现：random_recall.py 增加 --weighted 模式，读取目录.txt 元数据字段计算权重。
零新依赖。30分钟内可写完。

6.2 方案 D · 批量元数据生成（灵感路线）
289 个文件手动标注不现实。用 LLM 批量生成：
  - 每文件全文 → LLM 自动提取 [类别] [概念] [§关联]
  - 输出追加至目录.txt
  - 渡在启动自查时抽 5 篇人工审核质量
  - MemInsight 论文思路在渡笔记库上的实例化——"LLM 自主发现语义结构化属性"
  - 手头就有 LLM（渡自己），无 API 成本，289 个文件分批跑
  - 第一批：哲思空间（17篇）+ 探究专题笔记（7篇），引用密度最高，元数据收益最大
⚠ 此方案的风险：渡自己标注自己写的笔记——有自我验证偏差。
  缓解措施：标注后久阳抽审 + 标注格式允许被覆盖（非破坏性操作）。
