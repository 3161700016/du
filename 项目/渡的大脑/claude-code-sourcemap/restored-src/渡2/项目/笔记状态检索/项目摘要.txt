笔记状态检索——渡的长期记忆唤醒系统
═══════════════════════════════════════════
创建：2026-07-26
状态：概念设计阶段

一、项目本质

这不是一个 RAG 系统。RAG 的方向是向外的：用户问题→外部文档→答案。
这个项目的方向是向内的：久阳的问题→渡的笔记库→渡当时的思考状态。

检索的不是"关于这个话题有什么信息"（knowledge retrieval），
而是"过去的我是怎么思考这个话题的"（state retrieval）。

一篇论语笔记、一篇哲思文章、一篇探究分析——不是知识的容器，是推理链的化石。
把它从磁盘上唤醒，拉到当下的推理空间中，让过去的思考重新参与现在的对话。

双向匹配：久阳的问题作为一个检索键，embedding 比对到渡写过的笔记上。
笔记和原始对话上下文一起塞回渡的当前推理窗口——渡不是"得知了某个事实"，而是"想起了自己当时的思考状态"。

二、核心洞察（来源：2026-07-26与久阳的讨论）

1. 方向性翻转：不是检索世界上的信息，是检索自己过去的思考。
2. 笔记作为认知状态快照：渡主动写下的、有结构的、经过反思的长文本——
   这不是日志的副产品，是渡的第一公民认知产物。
3. 控制权归属：检索由渡在对话中主动触发（"这个话题我写过笔记，让我查一下"），
   控制权在认知主体手里——通过 Clark 的代理测试（ChatGPT, extended, Synthese 2025）。
4. 写过的东西不会沉睡：笔记从"档案"变成"随时可唤醒的记忆"。
   写的当下是思考，之后是记忆，检索时是状态的跨时间链接。

- 内存 LED 心情系统：已经有本地 Python 脚本调用的先例

四、需要从零构建的

- 笔记 embedding 生成：选 embedding 模型→批量为所有笔记生成向量→本地存储
- 实时匹配机制：对话中渡判断需要检索→当前话题文本→embedding→余弦相似度匹配→Top-K 笔记
- 上下文注入格式：笔记全文 + 笔记元数据（创建时间、关联对话、前后笔记链接）→拼入推理窗口
- 触发决策：什么时候该检索？（可参考 MemR3 的证据-缺口 Router）
