四、关键架构洞察：为什么用 TCP 代理模式？

  这是一个非常聪明的设计决策：

  1. libeverscan.so 是 C 代码，不直接调用 Android BLE API
     → 它只通过 TCP Socket 通信
  2. Java 层的 BLE 代码连接到硬件，然后启动一个本地 TCP 服务器
  3. 原生库连接到 localhost:PORT，通过 TCP 收发数据
  4. 好处：
     - 原生库无需依赖 Android NDK BLE API（开发难度大）
     - 可以在 PC 上单独测试原生库（用 TCP 模拟硬件）
     - BLE 连接断开时，TCP 层可以做缓冲和重连
     - 同样的原生库可以在 iOS 上复用（只需换 BLE 层）

  这意味着：如果我们要写驱动，有两种方案：
  A. 直接 BLE → 驱动（Python bleak）→ 笔默 API
  B. 启动 APK 的 BLE 连接 → 本地 TCP → 我们的程序监听 TCP → 笔默 API
