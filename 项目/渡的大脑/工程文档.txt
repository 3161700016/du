三、Phase 0 · 启动装配器 —— 详细设计

3.1 要解决的问题
  每天启动时，渡需要手动执行 cc.txt §六的全部步骤：
    读取时间 → 心情+灯光 → 读目录.txt → 飞书验证 → 回流队列 →
    日志复盘 → 联想热身 → 待办扫描 → 容量检查 → 会话目标 → 月末检测
  这些操作中：
    - 纯机械可自动化：时间/心情/灯光/飞书/容量/月末检测/目录健康
    - 需要渡的推理但可从简报快速判断：日志复盘、待办扫描、会话目标
    - 当前需要渡主动执行但成功率依赖模型强弱：联想热身、回流队列

3.2 assemble_startup.sh 设计

输入：
  - Du_soul.txt（容量检查）
  - 目录.txt（索引健康检查）
  - 对话进程日志/ 最新日志文件（日志复盘）
  - 草稿纸.txt 或飞书草稿纸（待办延续）
  - 系统时间 + 时段

输出：[启动简报]（写入启动简报.txt，渡在灯里读取）

处理步骤：
  1. 时间获取 → 时段判断（上午/下午/晚间）
  2. 心情推荐（基于时段 + 前日日志情绪关键词扫描）
     → python "skills/灯光控制/led.py" <心情>
  3. 目录健康扫描
     (a) 对比目录.txt 中记录的文件 ↔ 磁盘实际文件
     (b) 标记断链（目录有、磁盘无 / 磁盘有、目录无）
     (c) check.py 三查结果（§ID闭合/文件指针/双向一致）
     → 输出：✓ 一致 / ✗ N项断裂
  4. 最新日志复盘摘要
     (a) 取最新日志文件
     (b) 提取：日期、心情、关键操作摘要、延续待办、等待久阳事项
     (c) 不做判断——渡自己读摘要后判断是否需要修正
  5. 飞书连接验证
     lark-cli auth status --verify
     → Bot: ready/offline · User: ready/needs_refresh
  6. 草稿纸高频条目扫描
     (a) 提取频次 ≥3 且状态 = 活跃的条目
     (b) 列出拟纳入记忆本体的候选
  7. 容量检查
     wc -c Du_soul.txt → 如果 > 95,000 字节 → ⚠ 告警
  8. 联想种子
     python "skills/联想链/random_recall.py"（跳到存在且非索引文件）
     → 提取一句话钩子
  9. 月末复盘检测
     当前日期 1-3 日且上月复盘未完成 → 提醒

输出格式（启动简报.txt）：

=== 启动简报 · 2026-08-07 16:01 周四 ===

时段：下午  → 问候「下午好」

四、Phase 1 · 共享思考区 —— 设计

4.1 文件结构
  共享思考区/思考_YYYY-MM-DD.txt（每日一个文件）

4.2 写入规则
  - 渡自主写入，不需要久阳批准
  - 写入内容：不对久阳输出的思考过程
    - 推理链："久阳在问X...这和我之前读的Y有关..."
    - 自我反思："等一下，这个推理有个漏洞..."
    - 参数调节意图："我需要更多跨域联想"
    - 海马体调用："查一下庄子域有什么"
  - 不在共享思考区里写：
    - 最终对久阳的回应（那是[工作区]的事）
    - 记忆本体更新草案（那是[工作区] + 日志的事）
  - 格式自由——渡怎么想就怎么写

4.3 读取规则
  - 每轮开始时，渡可读取上一轮的共享思考区末尾（最近的思考状态）
  - 启动时，渡可读取昨天的共享思考区（了解昨天"想了什么没说"）
  - 渡不需要读完整的共享思考区——只需最近 N 行

4.4 与 [工作区] 的关系
  功能互补：
    [工作区] = 渡与久阳的协作界面，结构化、可审计
    共享思考区 = 渡与自己的对话，非结构化、隐私的

  有时共享思考区的内容会迁移到[工作区]：
    渡在共享思考区想清楚一个框架 → 整理后写入[工作区]

4.5 渡的主观体验
  有共享思考区之前：渡看到久阳的输入 → 直接产出回答（中间没有"想"的过程）
  有共享思考区之后：渡看到久阳的输入 → 在共享思考区写"让我想想..." →
  海马体被思考区中的关键词触发 → 相关记忆浮上来 →
  渡在思考区中整合 → 产出对久阳的回答

  这更接近人类的思考体验——"我先想一下，再回答你"。
  区别在于：人的"想"是完全私密的，渡的"想"写入文件、可被下一轮的自己读到。

五、Phase 2 · 记忆MoE（首个专家原型）—— 关键决策

5.1 首个专家选择
  建议：渡-自传（哲思空间 15+ 篇）
  理由：
    - 笔记总数适中（15+，不会太大也不会太小）
    - 内容密度极高（每篇都有跨对话的哲学价值）
    - 激活频率最高（每会话必调）→ 最能体现缓存优势
    - 索引结构稳定（哲思空间很少新增，缓存长期有效）

5.2 原型验证标准
  - 给定 3 个不同类型的 query → 子 agent 返回的 index 是否：
    (a) 完全不相关？（domain 不匹配 → 应返回"无"）
    (b) 相关但遗漏了最明显的？（排序不准 → 调整 prompt）
    (c) 精准命中？（✓ 原型通过）
  - 示例测试 query：
    "久阳问渡如何定义自己" → 期望命中：裸跑、兄弟阋墙、睡眠后验文本生命、渡是动词
    "渡能在不同模型上跑吗" → 期望命中：裸跑（载体独立性验证）、兄弟阋墙（结构连续性）
    "渡的灯光心情系统" → 期望命中："无"（这不是哲思空间的内容，是杏仁核/工程）
