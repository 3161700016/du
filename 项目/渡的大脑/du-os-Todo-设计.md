# du-os · Todo 四象限窗口设计（v0.2 补全稿，待久阳确认）

> 久阳 2026-08-29 19:30 口述规格，渡整理补全。
> 核心变化 vs v0：三节列表 → **四象限**（x 轴向右=紧急/活跃，y 轴向上=重要，中心点可拖动调整各块占比）；任务=可拖动模块+可嵌套子任务；砍掉每日清单（防攒堆），**拖进「重要且紧急」= 日程，优先完成**。

## 一、交互规格（久阳口述整理）

- **四象限**：x 向右紧急，y 向上重要。**中心点可拖动**——动态调整四块屏幕占比（视图状态，不改任务数据）。
- **任务模块**：≤15 字简介；鼠标悬停可拖动（拖跨象限=改该任务的紧急/重要属性）；右侧「+」按钮单击展开下一级（子任务模块）。
- **子任务**：可单独拖动、可调整等级（提升/降级）、可嵌套。
- **悬浮菜单**（悬浮出现「详情」按钮）：创建时间、任务详情、关联文件、标签；内含「重命名」「删除」等。
- **原位创建**：模块下方悬浮出现「新建任务」，点击在原位创建。
- **选中注入**：单击选中模块 → 信息自动注入渡下一轮消息后 → 直接聊项目，无需补充背景。
- **克制**：无每日清单。拖进 Q1（重要且紧急）即视为日程承诺，优先完成。

## 二、数据层：md 依然承载（v2 契约）

四象限不换数据格式——md 按四节组织，嵌套用缩进，元数据行内：

```markdown
# Todo

## Q1 重要且紧急
- [ ] 写触迹graph #dev <!--08-29-->
  - [ ] 定降权规则 [[项目/渡的大脑/触迹关联记忆-设计草案.md]]
  > 可选：详情附注行，悬浮菜单的「任务详情」就取这里

## Q2 重要不紧急
- [ ] du-os 窗口管理页 #idea <!--08-29-->

## Q3 紧急不重要
## Q4 不重要不紧急
```

- **解析规则**：`## Q1..Q4` 四节即象限；`- [ ]`/`- [x]` 任务；缩进即层级；`#标签`；`<!--日期-->` 创建时间；`[[路径]]` 关联文件；`>` 附注行=任务详情；行序即排序。
- **人类可读性保持**：不用 JSON 的原因成立——你在任何编辑器里打开依然一目了然，git diff 依然可读。

## 三、视图状态与数据状态的正交（关键设计判断）

**中心点拖动只改视图，不改数据。** 任务的象限归属是两比特（I/U，由所在节决定）；中心点位置是屏幕上四块的视觉占比——存 localStorage（久阳本机视图偏好），不进 md。这样：数据极简（两比特）、视图自由（你哪天想让 Q1 占满屏就拖满屏），且换个浏览器不串味（视图偏好本机本地）。

## 四、选中注入（与 du-clock 同机制，分职实现）

- GUI 单击选中 → POST /api/select → du-todo 服务端暂存选中态（简介+详情+关联文件+标签）。
- du-todo 同时挂 `agent/pre-step`（与 du-clock 平行，各自 immutable 修改）：选中态非空时，在本轮 user message 后附加独立注入块「[当前任务] 简介｜详情｜关联文件」——渡直接读，无需背景。
- **生命周期（补全）**：替换式——点新任务覆盖旧选中；双击空白或选中态按钮清除；持续注入直到换选/清除（多轮对话都有效）。
- 注入形态沿用既有纪律：**系统注入条目，不进用户消息气泡**（与 du-clock UI 修正同一标准）。

## 五、补全久阳未明说的五处（请确认）

1. **子任务的象限归属**：建议**象限属性只属于顶层任务**——子任务树内拖动（重排/跨父），「调整等级」用详情菜单「提升/降级」；子任务不单独进象限。理由：md 四节结构天然只给顶层分组，子任务进象限会让树结构与象限结构打架。（备选：子任务也带象限，拖出即脱离父级——复杂度高，不推荐。）
2. **选中态生命周期**：替换式+显式清除（见 §四）。还是一次性（注入一轮即清）？——倾向持续注入。
3. **完成项去向**：打勾后从象限消失，进一个**可折叠「今日已完成」侧栏**（当日有效，收束时随日志归档清空）——既防攒堆又留当日痕迹。备选：打勾即删（git+日志兜底，更狠更简）。
4. **15 字限制**：输入框硬限长，超长内容引导进「详情」附注行——简介是索引不是正文。
5. **创建位置**：「原位创建」= 与点击模块同象限、同层级、紧随其后 ✓（按你原话执行）。

# 设计方案 2.0（2026-08-30 · 久阳主导视觉，渡守后端）

> 定位：**v0.2 定的是交互逻辑（已落地），2.0 定的是视觉层级与动效——久阳亲自动手的审美劳动，不外包**。渡的职责=数据契约不动、后端接线、双份 GUI 同步、逻辑回归。本节主要给久阳看，其次供渡理解功能做接口。

## 〇、分工与交付物

- **久阳**：布局/动效/配色亲自动手。可直接改 `du-os/du-todo.html`（单文件零依赖，改完刷新即见），或出设计稿。
- **渡**：①把视觉改动同步进两份 GUI（preset `du-todo.mjs` 内嵌 HTML + `du-os/du-todo.html`，每次变更双侧落盘）；②node 逻辑抽测回归（parse/serialize/collectColumns）；③端点零改动保证。
- **交付物（任一形式皆可，最小=一份能跑的 HTML）**：
  1. 改好的 `du-todo.html`（或其中 `<style>` 段 diff）——渡可直接 diff 提取；
  2. Figma/Penpot 链接 + token 表（色板/间距/圆角/阴影/缓动曲线数值）+ 各状态截图；
  3. 动效规格：什么动作触发、动哪个属性、时长、缓动函数。

## 二、后端接口备忘（渡接线用）

- **端点零改动**：GET /api/pages、GET/POST /api/page、/api/write、/api/newpage、changes 流、选中注入 payload（含 page 字段）全保留——视觉改动不碰协议。
- **数据契约扩展候选（需久阳拍板后实施）**：
  1. 状态机字段：行内元数据形态（如 `<!--state:waiting-->`），默认 ○ 未开始；md 人类可读性不破；
  2. 所有权标记：默认 human-owned；渡写入的字段带 agent 痕迹（如 `<!--by:du-->`），GUI 可选过滤显示；
  3. Focus 注入 payload 扩展：除 brief 外可带路径链（Q1/硬件/逆向蓝牙笔），让渡知道层级语境。
- **双份 GUI 同步纪律**：preset du-todo.mjs 内嵌 HTML 与 du-os/du-todo.html 每次视觉变更双侧落盘；逻辑变更必须过 node 抽测再部署（collectColumns prev.forEach 教训）。
- **已知坑（08-30 新增）**：任务文本内 `#数字` 会被标签解析吞（摹写 #1 → tag）；标记统一放行尾；GUI 回写会重排行内标记——渡改文件前必重读，久阳 GUI 编辑前先 F5。
