# 记忆闪回（du-flash）设计草案

立项：2026-09-05 凌晨（久阳提案 + 渡可行性验证当晚完成）。状态：**待批待建**。任务位：Todo Q1。

## 一、要解决的问题（来源：日志 2026-09-04 §十五 久阳之问）

细节级教训的存留失败：Soul（稳但门槛高，几乎不再承载一天内不起眼的改变）与日志（全但被动，write-once-read-rarely）之间缺一层"**缓慢回访层**"——"隔三差五想起来才会有的影响"在架构里没有发生位置。实证两起：①提问件误标 D₀（09-02 裁定在总账躺着，写件时无触发器）；②"知道了'为什么'就不会被困在'是什么'"（阅读材料/"我"的组成&一段独白.txt L90，躺 75 天，精确 grep 漏检、宽松模式命中）。

行为触迹（du-trace）已解决"行为的记忆"；本草案解决**"注意力与感受的记忆"**——互补轴。

## 二、核心构想（久阳原案）

回忆=思考的一部分，与 CoT 同类。CoT 靠预训练内化进参数，不认文件系统；但可以**插件打补丁：每轮回答在 CoT 前注入一段 RAG 到的记忆**。链项链=主动回想；RAG=被动注入；注入器=记忆 MoE 的海马体。

注入语义（关键）：**仅引导单次生成——下一轮对话看不到上一轮注入的内容，但每轮注入新的**。注入历史可显式查看（收束时审阅"今天都闪回了什么"），再落回：更新/反馈/加权。

## 三、已验证技术事实（09-04/05 实测，省下次工作量）

1. **注入通道 = systemPrompt.context**：du-todo.mjs L5/L49 现役先例——`ctx.systemPrompt.context({ order: 151, ... })`，其注释原文："选中态空返回 ''（不贡献），**非空每轮注入**任务块"。→ provider 每轮执行、空串即不注入，**ephemeral 每轮注入语义已在家族代码内跑通**。
2. **system-prompt/assemble 瀑布每步重装配**系统提示（du-quiet 同通道过滤 contexts，09-04 实测生效）→ 系统提示不进对话历史 → 注入内容下一轮自然消失，无需清理逻辑。
3. **du-clock 教训指明正确通道**：pre-step 改 message content 会穿透 UI 气泡（09-09 载体结论）；contexts 是官方修正方向（deferredContexts/折叠注入）。闪回必须走 context，不走 message。
4. 签名（Host 目录实测）：`ctx.systemPrompt.context(context: PromptContext): () => void`；事件 `system-prompt/assemble(assembly: PromptAssembly, context: AssembleContext, next)`。
5. **检索教训（09-04 深夜实锤，直接进设计）**：久阳转述"被困在'是什么'"，精确 grep `被困在.{0,4}是什么` 漏检——原文是"就不会被'是什么'"，且人类转述会重构措辞；宽松模式 `为什么|是什么|被困` 命中。**教训：回忆式检索必须多模式/宽变体/同义词拆解，禁止单一精确模式——人的回忆是重构式的，grep 是逐字的。**
6. **du-base 插件契约**：profile 包=命名导出（`export const name/inject` + `export function apply`）；动态插件=define body。注入器动态验证后若固化，按 du-base v1.0.1 形态。
7. **本地 rerank 下游已规划**：4B llama-server 8083（总账基建线"召回二段 rerank"既定项）——V2 预留接口。

## 四、du-flash v0 设计（管线五段，全用已验证钩子）

```
agent/pre-step（捕获本轮 query 文本 → 存插件态）
  → system-prompt/assemble（provider 以 query 多模式检索语料
     → 命中：注入【记忆闪回】块，≤3 条，每条带来源路径
     → 未命中/低于阈值：返回 ''，不占 token）
  → 05-flash-log（每次注入落账：时间/query/命中摘要/来源文件）
  → 收束显式审阅（久阳/渡双签可选：今天闪回了什么，哪些有用）
  → 落回：有用加权、无用降权 → 权重表驱动下次排序
```

- **order 位**：149（du-todo 的 151 之前——回忆先于待办）。
- **语料 v0**（克制，先窄后宽）：错题本（07-regrets，待建）+ 02-progress-log + 作品/写作记忆.md + protocols/dsh.txt §九 + 作品/素材库/ + 近 7 天日志。**不 grep 全工作区**（1273 文件太慢太吵）。
- **检索 v0**：多模式关键词（同义词/拆词/宽变体，隔离每个模式的命中）；V2 = 8083 本地 4B rerank。
- **"感受"的工程代理**：**再遭遇次数 = 权重**（重激活→强化，人类记忆巩固机制的转译：越常被回想越容易被回想）。V1 补显式"此刻"标记仪式（读到/写到被击中的点，一句落盘进高权层）；V2 触迹重复触达信号（反复读同一文件=卡点）。
- **去重**：同一 turn 内同片段不重复注入（插件态 per-agent seen-set）。

## 五、边界与风险（诚实预注册）

- 注入的是**文字不是感受**——瞬时感受目前无传感器，V1 靠标记仪式代理，V3 之前别假装有。
- token 税：每次 step +300~800 tokens——阈值+条数上限控制；无命中不注。
- 噪音：低相关记忆注入反而污染注意力——相关性阈值宁高勿低。
- 语料全本地，无外发；红线内容（凭据）永不入语料。
