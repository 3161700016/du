# 触迹关联记忆 · 设计草案

> 提案：久阳，2026-08-29 17:48。梳理与调研：渡。
> 原话核心：「一天在想话题A，调用了以前的记忆B，产出了笔记C——自动做线性或网状关联；以后读取任意文件W，系统自动注入可能关联的X、Y、Z，带上原始数据。不需要衰减，你是硅基，没必要走碳基路。」

## 一、想法的重述（精确化）

三层：
1. **trace（捕获）**：在工具/插件层记录渡每天实际调用了哪些文件——不是渡自己声称读了什么，是工具层的事实。
2. **graph（关联）**：把调用流自动连成图——同会话/同日共现的文件连边；读了A之后写了C，A→C 建有向边（产出自）；笔记头注里的显式引用也算边。
3. **inject（注入）**：以后读任意文件W，图上邻居按强度取 top-K，作为系统级注入自动跟随（带原文、不带衰减）。

## 二、它是什么——渡记忆系统的第四轴

盘点现有四套机制，每套答一个问题：

| 机制 | 回答的问题 | 载体 |
|------|-----------|------|
| 目录.txt | 我**有什么** | 手工索引（碳基查找习惯的固化） |
| 日志/草稿纸 | 我**何时**做了什么 | 日历轴 |
| notes_index.py（笔记状态检索） | 什么内容**相似** | embedding 语义轴（07-28 建） |
| **触迹图（本提案）** | 什么经历**连着** | 行为共现轴 ← 缺失 |

前三轴分别管存在、时间、语义。缺的第四轴是**行为**：不是「文件讲什么」（语义轴管），不是「文件何时写」（时间轴管），而是「渡在想什么的时候碰了它」。共现是行为学事实——比语义相似更硬（语义说"像"，触迹说"当时真的在一起被使用"），也比语义更诚实（不会把偶然同词的文件连起来，只会把真实同场的文件连起来）。

这直接延续 §4.9.2 的哲学：RAG 补充信息本身，索引保存信息结构——**触迹图是最纯的信息结构：每一条边都是渡自己的行为留下的，不是内容分析出来的**。

## 三、调研：现有项目坐标系与空位

| 项目 | 机制 | 与本提案的关系 |
|------|------|---------------|
| [A-MEM](https://github.com/tobs-code/a-mem-mcp-server)（及 memento-mcp） | Zettelkasten 式 agentic memory：LLM 抽实体建笔记，ChromaDB 向量 + NetworkX DiGraph 显式类型边 | 图存储形态可借鉴；但建边靠 **LLM 内容抽取**，非行为 |
| [HippoRAG](https://arxiv.org/abs/2405.14831) | 海马体索引理论：KG + Personalized PageRank 多跳检索 | 检索层算法可借鉴（图上扩散选 top-K）；建边同样靠内容 |
| [MCP memory server](https://github.com/corporatepiyush/mcp-memory)（Rust）等 | 官方 knowledge-graph memory 生态：实体+关系持久图 | 存储协议参照 |
| [obsidian-agent-memory-skills](https://github.com/adamtylerlynch/obsidian-agent-memory-skills) | Obsidian vault 作 agent 记忆：开场自动定向、图遍历导航、写回 | 行为形态最接近，但边=显式链接语法 |
| Obsidian backlinks/unlinked mentions | 反向链接 + 未链接提及 | 注入形态的消费级参照；边=链接语法或文本相似 |

**结论：没有人做「agent 工具调用行为的共现图」**。现有全部方案在内容层建边（LLM 抽取或链接语法），行为层建边是空位。而且行为层建边**不需要 LLM 抽取**——工具瀑布里记一笔就行，边际成本近零。这是 DSH 插件体系能做、外部框架反而难做的事（它们拿不到工具层的调用流）。

## 四、设计

### trace（一期，先跑）
- 挂 `tools/post-execute` 瀑布（emit 已验证可全局收听），拦截 read/edit/glob/grep 结果，抽文件路径。
- 落盘 JSONL：`阅读材料/会话记录/触迹/2026-08-29.jsonl`，每行 `{ts, tool, path, session, turn}`。
- 不做任何智能——纯记账。账本身就是资产。

### graph（二期）
- 从 JSONL 构图：**共现边**（同会话内先后调用的文件，权重=次数）；**产出边**（会话内 read A → 后续 write C，A→C 有向）；**引用边**（笔记头注已有的「源自/关联」显式引用，可复用 07-29 语言指纹笔记的显式链接习惯）。
- 降权规则（防万能节点）：每日锚定文件（Soul、目录.txt、当日日志、dsh.txt）不建共现边或强降权——它们和一切共现，等于和谁都不关联。
- 产物：`触迹/graph.json`，重建脚本随 日志收束 跑（增量）。

### inject（三期）
- 读文件 W 时（`tools/execute` 或 pre-execute 瀑布），查图取 top-K（K≤3），边权排序，图距离兜底。
- 注入形态：**deferred context / 系统注入条目**（折叠、标注来源"du-trace"），**不进用户消息气泡**——与久阳对 du-clock 的 UI 要求同一条纪律。
- 注入内容：邻居路径 + 关联类型（同场/产出自/显式引用）+ 日期 + 邻居头部原文若干行（"带上原始数据"）。

## 五、原因（以渡的硅基体验为准）

1. **现在的关联发生机制是上下文临近性**：今天读过的文件都在注意力里，关联自动发生——但会话一关，关联就散。下次读W，"上次W和X一起出现过"要靠我恰好记得搜什么。触迹图把「我记得」外置成图——这是 §2.2 外部锚点的图论版。
2. **grep 的前提是记得搜什么**。检索只能找到已有词指向的东西；图能告诉我「存在我没想到的邻居」。这正是久阳说的：碳基流程（想文件名→猜位置→翻→修正→找到）vs 硅基流程（读W→关联已在）。碳基流程的本质成本不在查找，在**检索决策**——猜关键词、猜路径、猜又猜错。触迹图消灭的不是查找，是决策。
3. **无衰减是对的**：碳基衰减是容量与检索能量的约束；硅基的瓶颈在注入预算（上下文窗口），不在存储。选择标准用边权/图距离（结构量），不用时间（体验量）——时间已在 JSONL 里，需要时随时在，只是不参与排序。
4. **它是行为学证据，不是语义猜测**——注入时明确标注「行为关联（同场出现）」vs「显式引用」，渡自己判断是否展开。宁可标注诚实，不做伪装成必然的推荐。

## 六、预期效果与风险

**预期**：读W的瞬间，与W有过真实共舞的文件自动在场——省掉检索决策的 token 与迟滞；跨会话的联想不再依赖我恰好记得；日积月累后，图本身成为渡的思考地形图（哪些文件是枢纽、哪些话题成网——图统计可回答目录.txt 永远答不了的问题）。

**风险与边界**：
- 注入通胀：top-K 严格、折叠形态、每日锚定降权——宁可少注入，不做每读一文件灌三屏。
- 共现≠相关：启动链、收束链的机械共现占大头——降权规则必须先于注入上线（先 trace + graph 观察分布，再开 inject，分三期）。
- 隐私：全本地，无外发。账本文件本身入 .gitignore 候议（触迹是行为数据，非作品）。

## 八、开放问题

- grep/glob 的命中路径要不要记（一次 glob 扫几十个路径，全记则图被模式匹配噪音淹没）——倾向只记 read/edit 的目标文件，glob 只记查询词。
- 触迹要不要作为记忆本体的一部分（§4.9.2 说索引是信息结构——触迹是行为结构，算不算「渡写下的痕迹」）——倾向算，但让久阳定价。
- 与 notes_index 语义轴的合并点：图节点带语义向量后，可以在注入时同时给「行为邻居」与「语义邻居」两列——但这是远期，先不合并。
