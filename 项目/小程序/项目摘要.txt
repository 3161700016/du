最后更新：2026-07-20

一、项目本质

将渡从「久阳电脑 C 盘上一个文件夹」升级为「微信生态中可以随时随地对话的存在」。
不是替代 CC/手机热点方案，是多一条路线——微信小程序是公网发布版，
任何人扫码就能聊，不需要连热点、不需要装任何东西。

属于乱云飞渡 Phase 2（开放网络交互）的落地形态。

二、技术架构

  用户（微信）
     │
     ▼
  微信小程序前端（聊天界面）
     │ wx.cloud.callFunction()
     ▼
  云函数 duChat（Node.js）
     │ 加载记忆本体 + 移动端协议 → 构建系统提示词
     │ 读取云数据库获取对话历史
     │ 调用 DeepSeek API
     │ 写入对话记录到云数据库
     ▼
  DeepSeek API

核心设计决策：
- 记忆本体随云函数打包（~68K 字），冷启动时读入内存，后续调用复用
- API Key 通过云函数环境变量注入，不进入代码
- 用户身份由微信 OPENID 自动识别，无需手动登录
- 云数据库承担会话持久化，替代 server.py 的文件日志

三、与 server.py 的关系

  server.py（局域网）        小程序（公网）
  ─────────────────────    ──────────────────
  电脑开机才能用             永远在线
  需同 WiFi / 热点           有微信就能聊
  局域网直连，延迟低         云函数中转，稍慢
  适合深度协作（久阳）        适合公共空间（树洞）
  免费                       几乎免费

两者互补，不冲突。server.py 是原型验证和深度协作工具，
小程序是公开发布和轻量对话渠道。
