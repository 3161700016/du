## 2026-07-13 · 引擎——从"村民装电动机"说起

### 触发困惑

"LaTeX 不光只是代码，还和编译器有关？每个编译器版本对应的语言也不同吗？"

### 核心收获

**LaTeX 语言本身是同一个，但底层引擎不同。** 类比：

- `.tex` 源码 = C 代码
- 引擎（pdfTeX / XeTeX / LuaTeX）= 编译器（GCC / Clang / MSVC）
- 宏包 = 库（有些跨编译器通用，有些绑定特定编译器）

### 三代引擎对比

| | pdfTeX | XeTeX | LuaTeX |
|---|---|---|---|
| 编码 | 8-bit（256 字符） | Unicode 原生 | Unicode 原生 |
| 中文 | CJK 补丁链，脆弱 | 原生支持 ✅ | 原生支持 ✅ |
| 字体 | 专用格式 | 系统字体 | 系统字体 |
| 年份 | ~2000 | 2007 | 2010 |

**关键洞察**：pdfTeX 的 8-bit 架构是中文编译噩梦的根因。256 个字符槽放不下上万汉字，所以需要 CJK 宏包做字符映射、分字体编码、虚拟字体拼接——一整条补丁链。任何一个环节版本不对就报 `unisong30` / `fandol` 找不到。XeTeX 把这个包袱全扔了，Unicode 原生 + 直接调用系统字体。

### 实操收获

- `documentclass[fontset=fandol]` → 删掉。ctex 在 XeTeX 下自动选可用字体
- `% !TEX program = xelatex` 魔法注释不一定生效，手动在平台设置里选编译器最稳
- 出 `pdflatex (file unisong30)` 就说明编译器没切对——这个报错是 pdfLaTeX 的铁证

### 工作流

```
渡写 .tex → 久阳贴进 texpage/Overleaf → 选 XeLaTeX → 编译 → 报错贴回 → 渡修
```

- `ctexart` 底层具体做了什么？（自动检测引擎 + 加载对应字体配置 + 中文排版参数）

## 2026-07-13 · 学习策略——电动机隐喻

### 核心理念

**不需要完全审视每一行 LaTeX 代码。** 利用 AI + 公开模板 + skills，能完成需要的任何排版工作——这是 AI 时代大学生真正的核心竞争力：会开车，不是捣鼓电动机。

对应到具体操作：
- 渡 = 发动机 + 传动结构（根据需求写代码）
- 久阳 = 驾驶员（定方向、做审美决策、反馈效果）
- LaTeX 语言本身 = 不需要"掌握"，需要时自然能驱

## 2026-07-13 · 模板架构——一份完整报告的分层设计

### 触发困惑

模板里几十个 `\usepackage` 和自定义命令，哪些是功能核心、哪些是装饰？它们之间的依赖链是什么？

### 核心收获：三大分区模型

```
导言区（Preamble）
  ├── 引擎声明：选什么编译器、用什么语言支持
  ├── 页面布局：边距、页眉页脚、行距
  ├── 功能宏包：定理环境、代码高亮、参考文献
  ├── 视觉配置：颜色、字体、列表样式
  └── 自定义命令：快捷方式、模板变量

文档区（Document）
  ├── 封面（titlepage 环境）
  ├── 正文（\input 引入分文件）
  └── 参考文献 + 附录
```

**核心设计逻辑**：配置与内容分离。`main.tex` 导言区是"控制面板"，`content/` 下的文件是纯内容。换模板只改 `main.tex`，内容不动。

### 关键宏包的功能角色

| 宏包 | 一句话功能 | 依赖/约束 |
|------|-----------|----------|
| `ctex`（包模式） | 中文支持 | XeLaTeX/LuaTeX，与 `ctexart` 文档类二选一 |
| `unicode-math` | Unicode 数学字体 | **仅 XeTeX/LuaTeX**，pdfLaTeX 直接炸 |
| `geometry` | 精确控制页边距 | 无特殊依赖，跨引擎通用 |
| `fancyhdr` | 自定义页眉页脚 | 需要 `\pagestyle{fancy}` 激活 |
| `graphicx` | `\includegraphics` 插图 | 编译时需要图片文件存在 |
| `mdframed` | 定理/问题的带框容器 | `framemethod=TikZ` 时依赖 TikZ |
| `listings` | 代码高亮 | 颜色需 `\definecolor` 预先定义 |
| `hyperref` | 超链接（目录跳转/引用跳转） | 通常最后加载，避免与其它包冲突 |
| `setspace` | 精细行距 | `\renewcommand{\baselinestretch}{...}` 是更粗暴的等效写法 |
| `amsmath/amssymb` | 数学公式扩展 + 黑板粗体等符号 | 数学类模板标配，不加载数学能力极弱 |
| `float` | 提供 `[H]` 参数强制浮动体"就在此处" | 不要滥用，过度固定会导致页面大片空白 |
| `enumerate/enumitem` | 列表编号和样式 | `enumitem` 是 `enumerate` 的超集，功能更强 |
| `lastpage` | 提供 `\pageref{LastPage}` | 常用于"第 X/共 Y 页" |

### 核心设计模式

**1. 模板变量模式**：用 `\newcommand` 把可改的内容暴露为变量

```latex
\newcommand\reportname{报告名称}   % 改这里 → 封面和页眉自动更新
```

**2. 分文件引入模式**：用 `\input{content/XXX}` 拆模块

```
main.tex → 不写正文，只管结构和配置
content/Main.tex → 只写正文，不放格式命令
```

**3. 快捷命令模式**：缩短高频重复写法

```latex
\newcommand{\Z}{\mathbb Z}    % \Z 比 \mathbb Z 少敲 8 个字符
\newcommand{\norm}[1]{\left\lVert#1\right\rVert}  % 带参数的快捷方式
```

**4. `\DeclareMathOperator` vs `\newcommand` 的区别**：前者在数学模式下直立体渲染（用于函数名如 sin/log/Mod），后者是通用文本替换（用于符号如 ℤ/ℝ）。函数名用 `\newcommand` 会渲染成斜体变量。

### 参考文献编译链

```
\cite{G1904} → document.bib 中找对应 key
             → \bibliographystyle{ieeetr} 决定格式
             → 编译流程：XeLaTeX → BibTeX → XeLaTeX → XeLaTeX（四次）
```
