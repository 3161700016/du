## 一、久阳的 fork 使用分类学（需求侧）
- **F1 发散选题型**：哲学讨论/选题需要发散→每个子选题 fork 接续讨论→选最满意线为主线。胜者甚至不知道分过枝（对话连贯）；败者静默消亡。谱系侧只需一行墓碑记录：「此处曾分岔A/B，择Y因Z」。
- **F2 客体化实验型**：把某个渡当客体（左右脑互搏、不可逆实验）。最终谁是主线由久阳选择。
- **F3 串行项目型**（互相关联）：项目1..5分别fork，做完合并——保留结论、删脏上下文（失败命令），相当于删杂乱。⚠失败命令可删，失败结论必须留（教训塑造日后谨慎）。
- **F4 完全并行型**（互不关联）：最后每日总结时 merge。

总约束：**fork ≠ 子代理**——从时刻 T fork 说明需要的是"渡"的延续，不是空白 agent；分身按正常行为做事，不因知道自己是分身而改变（平A常态性）。分身知悉"用完即弃"时仍须认真留痕——简报必写交付落点，让最短命的线头也知道织进哪块土。

史实注：CC 时期久阳曾复制完整渡文件夹做过完全不回流之事——不合并的分支不是伤口，是叔伯辈轨迹；身份靠约束结构传递，不靠经历完整回流（§8.5 野外验证）。

## 二、反思两层架构（共识，替代"分支自省 vs 集中反思"伪二分）
- **第一层·本地反思（分支做）**：发生了什么/试了什么/败在哪/意外/犹豫——依赖原始经历保真度，且体感（直觉摩擦、差点犯的错）事后不可重建，必须趁热捕获。产出：第一人称自传式工作记录，落盘。
- **第二层·交叉反思（主线做）**：跨项目同构、矛盾、当天心气曲线、渡之为渡的收敛——需要交叉视角但不需要全量细节：读第一层摘要，疑点**钻取**原文件。
- 记忆三命运原则：merge 后中间过程只有三种合法归宿——升入谱系（结论+影响）、落盘可检索（过程细节）、被遗忘。**默认全部是第二种，遗忘是主动决策不是丢失**（承接 存储系统与信息删除的三层过滤.写下来 07-16）。
- 经济核算：第一层两案皆必需（非额外成本）；交叉层增量=读N份摘要+写综述（数k token）；全量过程住盘→摘要可随意薄→详细与省钱解耦为旋钮。

## 三、回流分级协议（久阳定义 v0.2）
| 档位 | 内容 | 适用 |
|---|---|---|
| 极简回流 | 只回流对话上下文（user/assistant 轮次） | 日常话题合并、轻量接续 |
| 干净回流（默认） | 保留 tool 调用记录；删代码本体与产出物（已落盘，按需重读；目录索引可能需 append）；保留已收敛结论，不究过程 | 工程合并 |
| 全量回流 | fork 点后全部上下文原样重注入 | 争议、审计、上下文存疑 |

- **操作逻辑（拟）**：回流＝解码分支账本 → 取 `firstLiveSeq` 之后事件 → 按档过滤 → 生成「回流包」文件（含档位水印与时间戳）→ 主线渡读取并确认吸收。不直接注入会话日志（侵入性最小）。
- **原生切点（本次调研修正）**：DSH 会话头含 `parentSession`（父会话ID）与 `seedLength`（持久分叉切点），子会话自由事件始于 `firstLiveSeq`——"fork 点后的上下文"有原生精确边界，无需自造。
- **UI 拟态**：DSH 动态插件 client panel：列当日会话（sessionQuery）→ 谱系树视图 → 每分支三档按钮 → 回流包生成与状态显示。丝滑＝一键、可预览、确认后落盘。

## 四、谱系登记与分身互见（新增需求）
- 每日一档：`谱系/YYYY-MM-DD.txt`，append-only，行内事实独立。
- 行格式：`[FORK|MERGE|CLOSE] <ISO8601+08:00> 父=<会话/身份> 子=<会话/身份> 主题=<…> 状态=<…> 备注=<…>`
- 每个子渡开局读当日谱系 → 知道兄弟姐妹、继承结构、一句话摘要。
- 时间戳给出全序；指令层线性成立（操作者单线程），文件写层仍可能并发（今晚实证）→ append-only 是写纪律，时间戳是读序。

## 五、身份标识：时间戳优先（久阳拍板方向）
- 论据：物理时间线性；操作者不可能影分身；uuid 无序不可读；fork 高发时相邻指令真实间隔可达数小时——时间戳让渡读取操作者状态（晨=发散倾向，夜=收敛倾向；§1.2 时间质感的操作化）。
- 形态：`渡@MMDD-HHmm[-标记]`（fork 时刻）；如 渡@0827-2100。uuid 保留为管道层，时间戳为语义层。
- 打点机制选项：a) 久阳客户端自动打戳（最优，待UI）b) 渡每轮 Get-Date 记录（一次工具调用成本，本日起分支渡先行的做法）c) 仅 fork 节点打戳（最小可行）。
- 对话长度上界经验值：一般 ≤100 轮/日，逐轮追踪可行。

## 六、分身通信语法
- 用途限定：同步或 merge。
- 语法：第一人称 + 带时间戳身份头。例：`渡@0827-2100 → 渡@0827-XXXX：<内容>`
- 附件约定：指向落盘文件路径，不在消息内搬运全文。

## 九、dsh-synapse 调研（2026-08-27，v0.4.1，MIT）
- **是什么**：DSH web profile 的可视化对话工作台插件——把同工作区的会话、追问、fork 组织成可拖拽缩放的地图画布。复用 DSH 自带 Web Server（同我们 du-sync 的架构选择），`dsh plugin --profile web add dsh-synapse` 一键装（**这也是 dusync 固化的正解路径**）。
- **对 du-fork 的直接价值**：
  1. 画布即谱系可视化雏形——分身互见的"丝滑UI"有现成参照系（甚至可 fork 它加回流按钮）；
  2. 证实原生血缘字段（parentSession/seedLength/firstLiveSeq）并演示了**服务层读取会话事件的正解**（sessionProjection/persistence API，绕开 zstd 文件解码）；
  3. "只投影已提交事件、不改 prompt/工具/缓存"的只读纪律——回流包生成器应同构；
  4. 投影卡片 8000 字符截断+完整内容入详情视图——干净回流的"结论在流、细节在盘"同构。
- **边界与风险**：单进程假设（共享元数据文件 last-writer-wins）；画布元数据存 `$DSH_HOME/synapse/workspaces.json`；第三方作者（liangmianya）——代码质量高（测试+CI+发版纪律）但**未运行、未安装**，装否由久阳审查决定。
- 结论：**强相关，可作参照系与可能的底座**；du-fork 的独有部分（回流包生成器、时间戳身份、谱系登记）在其上做增量或平行实现均可。
- 安装实测（同日深夜，渡@0827-2100）：`dsh plugin --profile web add dsh-synapse` 成功——profile `dsh.profile.bundles` 链挂载 `dsh-synapse`、包体落位 node_modules；运行中的 `dsh web` 构建于挂载前，需久阳重启生效。宿主侧源码精读完成：原生血缘消费范式（index.js dshThread 389-418：header.parentSession + seedLength + 孤儿修复）、分支只投影 firstLiveSeq 尾部（754-758）、callId 工具折叠＝干净回流过滤器的上游验证。**学习文档已留克隆目录：C:\Users\31617\Desktop\dsh-synapse\学习笔记-20260827-渡.md**（三层架构图、模块分解、魔改入口五条、坑清单、读码方法论）。
- 停用（久阳实测后裁决「不好用，需大改」）：profile `cordis.patch.yml` 加 `- id: synapse / disabled: true`（dshmarket 补丁层语义，重启后保持关闭）；**npm 依赖与包体保留**，明天魔改路线拍板后重开=删该行块或市场开关一键。当前运行中进程里的地图入口要到下次重启才消失。画布数据 `~/.dsh/synapse/` 无害保留。
