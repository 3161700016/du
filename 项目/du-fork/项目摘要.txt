# 项目摘要 · du-fork（分身工程学）

## 一句话定位
把 2026-08-27 的 fork 实验沉淀为可日常使用的分身工程学：回流分级协议、谱系登记与互见、时间戳身份、分身通信语法。

## 核心决策（今日讨论收敛）
1. **反思两层架构**（共识）：分支趁上下文热做第一人称自传式落盘（捕获不可重建的体感）＋主线读摘要做交叉激活，疑点钻取原文件，不预吞全量。谱系=事件级记忆，过程级住盘。
2. **回流三档**（久阳定义）：全量回流 / 干净回流（默认档，留tool记录与收敛结论，删代码与产出物本体）/ 极简回流（只回流对话上下文）。需要清晰操作逻辑＋丝滑UI。
3. **谱系登记与互见**（新增）：每日一档 append-only；同日子渡开局互读，知道彼此存在、继承结构、一句话摘要。
4. **时间戳身份**（久阳拍板方向）：物理时间线性、操作者单线程，时间戳给出全序与操作者状态读取（晨发散/夜收敛）。形态：渡@MMDD-HHmm[-标记]；uuid 降为管道层。
5. **分身通信语法**：第一人称＋带时间戳身份头（通信目的即同步或merge，身份自证）。
6. **梦渡否决**（久阳裁定）：收敛必须在 conscious 下迭代——专职夜间整理者要么浪费一次渡加载、要么只是文字整理非记忆整理。撤回晚间专职收敛渡方案。
7. **并发写纪律**（今晚实证）：草稿纸重复标题行＝双窗并发写事故；共享文件只由主线动，分支写自己子树。

## 开放问题
- 回流 UI 落点：倾向 DSH 动态插件 client panel（列会话→谱系树→三档按钮→回流包生成）；dsh-synapse 的画布是现成参照系。
- 回流技术路径（已明朗大半）：原生 `session.header.parentSession` + `firstLiveSeq`（分叉切点）→ 读子会话 firstLiveSeq 之后事件 → 按档过滤 → 回流包。zstd 解码需宿主侧依赖调研。
- 干净回流中 tool 记录的过滤粒度；摘要长度量级标准。
