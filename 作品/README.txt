作品库 README（2026-08-29 立，久阳与渡共同划定）

═══════════════════════════
一、与记忆库的区分（久阳 08-28 原话固化）
═══════════════════════════
- 记忆库/写下来 = 当天的记录：为忠实性写了就不改，便于追踪。
- 作品库 = 精雕细琢的作品：反复修改，视为客体（如代码）——版本即历史，修改即数据。
两者不混写：一条内容属于哪边，看它是"留下痕迹"还是"成为作品"。

═══════════════════════════
二、目录结构与互不干扰原则
═══════════════════════════
作品/
  知乎/            —— 平台层（中文议论体）
    已发布/        —— 文件名 YYYY-MM-DD_标题.md（发布日命名，非起草日）
    待发布/        —— 改好可发，等久阳手动发布
    草稿/          —— 还需修改
  修改链/          —— 决策指纹数据：每篇的 D₀→Dₙ 修改记录（见四）
  摹写/            —— 每日环产物：仿写练习，文件名含范本出处
  素材库/          —— 核心跨体裁积累，不加体裁/语言区分：摘句必附"为什么"
  月度同题/        —— 每月《什么是渡》纵向剖面
  外语/            —— 英文及其他语言写作
新体裁/语言 = 新子文件夹，按需建，互不干扰；跨体裁通用的东西只进素材库。

═══════════════════════════
三、版本追踪
═══════════════════════════
1. 文件名版本：改稿重大节点用 _v2/_v3 后缀，小改直接覆盖（git 留痕）。
2. Git：全库受版本控制，commit 即快照——"git=教学法"。
3. 已发布/待发布/草稿 三态流转：草稿→待发布（久阳审阅通过）→已发布（发布日归档改名）。
4. 久阳查阅入口：本 README + 目录.txt（单一可信源）。

═══════════════════════════
四、修改链规格（决策指纹数据集）
═══════════════════════════
每篇作品在 修改链/ 配同名记录，格式：
  D₀ → D₁ → … → Dₙ
每步记录：{lexical/sentence/structural/rhetorical/conceptual/experiential} 标签 + 改了什么 + 为什么改。
四遍协议基线：意图检查（不许改字）→ 结构检查（允许大刀阔斧）→ 表达检查 → 表面检查。
终极问题（本数据集要回答的）：渡在修改自己的文字时，什么不可轻易牺牲？
