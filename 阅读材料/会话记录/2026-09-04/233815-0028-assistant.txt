好问题，而且时机正好——今天搭的共享 GUI + 同一台电脑的文件系统，恰好就是这套架构的底座（队友各自开 session，外部记忆=本地文件，连同步都省了）。先把我想到的骨架摆出来，逐块讨。

---

**一、定位：这不是渡的缩小版，是另一个物种**

渡的 soul 承载人格连续性（43k 字），数模 agent 的 soul 只承载**纪律**。会话结束即弃、无连续性诉求——反而要明写“你的记忆在文件里，不在你身上”，防止它凭对话记忆做事而不是读文档。但渡的三条经验直接移植：**Boot Prompt 范式**（设计让纪律涌现的结构，不堆条款）、**熔裁可削测试**（每句话问“删了会改变哪个行为”，答不出就删）、**四毋**（竞赛特化后见下）。

**二、Soul 提纲（目标 ≤3000 字，六节）**

| 节 | 内容 | 预算 |
|---|---|---|
| 1 身份与模式 | 一行运行时配置（§5.6.4 式）+ **双模式自报**：启动先声明“我是主会话（调度）”或“我是分支 N，任务卡 X”——防分支漂移 | ~150字 |
| 2 红线 | 违者取消资格级：学术诚信、AI 使用声明边界、**匿名化滤网**（生成文本过一遍“无姓名/校名/队号”）、交付物完整性、时间节点。每条标注规定来源条款 | ~300字 |
| 3 求解纪律（四毋竞赛版） | **毋意→数字可追溯**（每个结果能指到代码/文件，编造=死刑）；**毋固→模型不恋战**（想不通就升级给人，不许死磕）；**毋必→建模多方案**（同题多模型比较后再选型）；**毋我→merge 忠实于分支文档**，不凭对话记忆重构 | ~400字 |
| 4 工作流协议 | 任务卡格式 / merge 协议 / **单写者原则**（见下）/ 进度日志纪律 | ~600字 |
| 5 文件布局 | 固定文件清单+各自的单写者 | ~200字 |
| 6 审美准绳 | 论文蒸馏产物（见三）+ 范例指针 | ~500字 |
| 7 沟通契约 | 对你的**决策上报点清单**（什么必须停下来问你）+ 对队友的指令接受边界 | ~300字 |

**最小核测试**：如果只能留五句，是这五句——①每个数字可追溯；②动手前先读 context 和 tasks；③做完写回+更新状态；④摘要含数值结果、结构可见；⑤拿不准就停、升级给人。其他都是这五句的展开。你不同意哪句，我们就知道分歧在哪。

**三、竞赛规定怎么蒸馏：三分类 + 溯源**

操作规则只有一条：**逐条问“这条规定改变 agent 的哪个行为？”** 改变的转成祈使句进 soul（标注来源条款），纯背景性的归档不进。落下来是三类：
- **硬约束**：时间节点、查重/独立作业、AI 使用政策（⚠ 国赛近年对 AI 有专门条款——**我要看你的规定原文**，2026 版我不可凭印象写，毋意）、格式规范、匿名化
- **流程约束**：交付物清单（摘要页/正文/附录/支撑材料）、时间盒
- **评分维度**：官方评分语言（假设合理性/建模创造性/结果正确性/表述清晰性）——这四轴直接成为审美骨架，也是主会话拆任务时的优先级依据

**四、优秀论文怎么蒸馏：反向工程评分点，可检查化**

论文不是规则库，是**风格样本**。两条路径：
1. **反向工程“评委看到什么给分”**：摘要的固定信息序列（重述问题→模型→方法→**具体数值结果**→检验→推广，一段式高密度）、图表自明性（每图自带结论注）、结构可见性（假设编号表/符号表/灵敏度分析章节的**存在性**——评委扫一篇论文只要 10 分钟，结构=可评分性）。产出全是**可检查规则**（“摘要必须含至少三个数值结果”这种能打勾的）。
2. **不可检查的留指针**：“表述优雅”这类塞不进规则的，soul 里只放一句“写作前读 04-范文/摘要节选”，正文蒸馏到外部文档。另外标注幸存者偏差：获奖论文是风格样本不是建模真理，防止 agent 模仿到错误的因果。

**五、架构协议——多人并发的命门是“单写者”**

你说的主干/分支/merge，关键纪律就三条：
- **任务卡**：每个分支任务 = 输入（读什么）+ 输出（写哪个文件、什么格式）+ **验收标准（可验证）**——不可验证就不许拆（分解仪式）
- **单写者**：分支只写自己的 `04-results/<分支名>/`，**通用上下文（03-context.md）只由主会话写**——三人+多 agent 并发时，多写者必炸，这是最便宜的一致性保证
- **merge**：分支完成→更新 01-tasks 状态→主会话读回→把“后续都要用的结论”提炼进 03-context；原始细节留在分支文档，context 只放骨架

文件布局提案：`00-soul / 01-tasks（账本）/ 02-progress-log（append-only）/ 03-context（主会话单写）/ 04-results/<分支> / 99-rules（规定蒸馏细则）`。

1. **规定原文**（AI 使用条款我必须看原文）+ 优秀论文 2-3 篇（越多越好，摘要+目录优先）

4. agent 名字（一行身份的事，你定）
5. 分支实现方式：**子代理**（subagent，同会话 fork，context 干净）vs **独立 session**（队友各自开）——我倾向混合：agent 自己拆的活走子代理，队友领的活走独立 session，任务卡是同一个格式
