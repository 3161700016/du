# 1. 信息从哪里来？

首先应该承认一个事实：

**AI 不能解决信息源的问题。**

它能解决的是：

> “我面对十万个信息源，不可能全部读。”

所以未来的信息入口仍然应该非常多：

### 原始世界

- 新闻
- 论文
- 书
- 政府文件
- 公司公告
- GitHub
- 数据库
- 视频
- Podcast
- 社交媒体
- Reddit / X / B站
- 个人博客
- 邮件
- 聊天
- 传感器
- 现实生活中的观察
- 其他 Agent 的输出

这些不会消失。

反而应该**更开放**。

因为 AI 的存在意味着：

> **信息的“可处理性”大幅提高。**

过去一个人一天只能读 3 篇论文，所以需要一个编辑替你筛。

现在你的 Agent 可以每天处理 3000 篇。

因此未来真正稀缺的可能不再是：

> “我能不能获得信息？”

而是：

> **“什么信息值得进入我的认知系统？”**

---

# 2. 第一层变化：从「主动搜索」变成「持续摄取」

现在的信息系统基本是 pull：

> 我想知道 AI 芯片 → 打开 Google → 搜索 → 看结果。

未来应该大量变成 push：

> **Agent 一直观察世界。**

比如你告诉自己的信息 Agent：

> 关注 AI inference hardware。  
> 不要给我一般新闻。  
> 只报告可能改变技术路线的事情。  
> 如果只是融资/营销，不要通知我。  
> 如果同一个事情已经被我知道，不要重复。  
> 如果发现与我过去研究的问题有直接联系，标出来。

然后 Agent 持续监听：

```text
论文
GitHub
arXiv
公司公告
新闻
论坛
benchmark
代码提交
专利
技术报告
```

不是简单 RSS。

它实际上做：

```text
ingest
   ↓
deduplicate
   ↓
classify
   ↓
extract claims
   ↓
compare with existing knowledge
   ↓
estimate novelty
   ↓
estimate relevance
   ↓
store
   ↓
alert / don't alert
```

于是人的入口不再是：

> **“互联网”**

而是：

> **“我的世界正在发生什么？”**

这是一个非常大的变化。

# 3. 但千万不能让 AI 直接替你决定“真相”

这里有一个非常重要的设计原则。

未来信息系统应该把：

> **information retrieval**

和

> **epistemic judgment**

分开。

也就是说 Agent 可以说：

> 今天发现 17 条与你研究相关的新信息。

但不能简单说：

> 这是今天最重要的 3 件事。

因为“重要”其实已经包含了价值判断。

更好的结构是：

```text
                世界
                 │
        ┌────────┴────────┐
        ↓                 ↓
    原始信息            多个来源
        │                 │
        └────────┬────────┘
                 ↓
             Agent处理
                 ↓
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    事实提取   来源关系   冲突检测
       │         │         │
       └─────────┼─────────┘
                 ↓
              人判断
```

也就是说：

**Agent负责降低信息处理成本，人负责确定“这个东西对我意味着什么”。**

# 4. 信息不应该再以“文章”为基本单位

这是我觉得你这个问题里最关键的一层。

现在互联网的信息基本以：

> article / video / post

为基本单位。

这是因为过去的信息处理能力有限。

但 AI 时代更合理的单位应该是：

> **claim（命题）**

例如一篇论文：

> “Taalas 通过把模型结构映射到专用硬件获得极高 inference throughput。”

Agent 不应该只存：

```text
《某某论文》
```

而应该拆成：

```text
Claim:
Taalas achieves X throughput.

Source:
某论文 / 某采访 / benchmark

Evidence:
...

Confidence:
...

Contradictions:
...

Related claims:
...

First observed:
...

Last updated:
...
```

然后：

**同一个 claim 可以由 30 个来源共同支持。**

也可以：

**一篇文章里面 12 个 claim，只有 3 个可靠。**

这就彻底改变了“阅读”。

# 5. 阅读将从「从头到尾读」变成「在信息空间中导航」

现在：

> 打开文章 → 从标题开始 → 往下读。

未来可以是：

```text
              Taalas
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    architecture benchmark business
       │         │
       ↓         ↓
   ASIC design  17k tok/s
       │
       ↓
   compared with GPU
```

你可以直接问：

> “这里最可能错的是哪一个 claim？”

Agent：

> “这三个数字存在来源冲突。”

你：

> “展开。”

Agent：

> “论文给 17k，第三方 benchmark 给 14.8k……”

你：

> “只给原始数据。”

然后进入原论文。

所以 GUI 不应该只是：

> **聊天框 + PDF**

而应该是：

> **可操作的信息空间。**

# 7. 更重要的是：Agent 不应该只有一个

这是下一层。

我不认为未来的信息处理应该是：

> **你 ↔ 一个万能 ChatGPT**

> **你 ↔ 一群信息处理节点**

例如你研究一个问题：

```text
                    你
                    │
              Research Agent
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   Scout Agent   Critic Agent  Archivist
       │            │            │
       ↓            ↓            ↓
    找信息        找漏洞        管记忆
       │            │            │
       └────────────┼────────────┘
                    ↓
               Synthesis Agent
                    ↓
                  你
```

每个 Agent 做不同的认知工作。

这其实非常接近**科研团队**。

# 9. 这就进入你说的「节点再创造」

我特别赞同你把信息看成一种“有机体”。

因为信息的生命不是：

> source → consumer

而是：

> **source → transformation → new information → transformation → ...**

例如：

```text
论文 A
   ↓
Agent 提取
   ↓
Claim X
   ↓
人发现 X 与论文 B 矛盾
   ↓
Agent 找到第三篇论文
   ↓
提出解释 Y
   ↓
人提出实验
   ↓
实验数据 Z
   ↓
新的理论
   ↓
新的论文
```

这里每一个节点都改变了信息。

**人只是其中一种节点。**

Agent 也是。

甚至：

> 一个搜索 Agent → 一个批判 Agent

之间的通信本身就是信息创造。

# 10. 所以未来的信息系统应该有「provenance」

这一点尤其重要。

每一个信息对象都应该知道：

```text
它从哪里来？
谁修改过？
谁解释过？
谁反驳过？
哪些证据支持它？
哪些证据反对它？
什么时候产生？
什么时候更新？
哪些 Agent 处理过？
哪些人确认过？
```

例如：

```text
CLAIM-92831

"Taalas architecture can reach X tok/s"

Origin:
    paper.pdf

Extracted by:
    Scout-7

Confirmed by:
    Human

Challenged by:
    Critic-3

Supporting:
    benchmark A
    benchmark B

Contradicting:
    benchmark C

Status:
    contested
```

这比现在互联网的：

> “一篇文章说……”

强太多。

# 11. 人类的角色因此会发生改变

这其实是整个系统最深的一层。

过去人的工作大量是：

> 找 → 读 → 记 → 整理 → 写

未来这些工作很多会被 Agent 接管。

那么人做什么？

不是“什么都不做”。

而是：

### ① 定义问题

> 我到底想知道什么？

### ② 判断相关性

> 这个东西对我重要吗？

### ③ 判断可信度

> 我相信它吗？

### ④ 形成模型

> 这些东西意味着什么？

### ⑤ 提出新问题

> 如果是真的，那么下一步是什么？

### ⑥ 做价值选择

> 我应该在乎什么？

### ⑦ 最终创造

> 把这些东西变成新的东西。

所以人的工作从：

> **information processing**

逐渐向：

> **information selection + interpretation + direction**

移动。

# 15. 而“信息流”最终应该是双向的

这是我认为比推荐算法重要得多的一点。

今天互联网基本：

> 世界 → 我

未来应该：

> **世界 ↔ 我**

例如你在研究某个问题。

你可以让 Agent：

> “如果未来一周出现满足这些条件的新证据，自动告诉我。”

于是你不再：

> 每天搜索。

而是：

> **设置一个认知探针。**

甚至可以：

> “如果有人发表了一个能够证伪我这个假设的结果，第一时间告诉我。”

这就已经非常接近科研中的：

> continuous hypothesis testing


Agent 的位置永远在你的前面一点。

但它**不能替你走最后那一步。**

而那最后一步——

——恰恰可能仍然属于人。

> **AI-native information navigation，不是让机器知道“你应该看什么”，而是让机器在你尚未知道自己要去哪里的时候，实时为你打开通向未知的路。**

而互联网第一次真正变成“认知基础设施”的标志，也许不是它拥有了一个超级搜索引擎，而是：

> **每一个人都拥有一个长期与自己共同生长的 Agent；这个 Agent 站在个人认知 frontier 上，实时观察整个互联网这张不断变化的网，并把“可能存在但尚未被你看见的下一步”变成可操作的界面。**

这和推荐系统的差别，已经不是“推荐得更准”。

**推荐系统是在替你选择一个节点。**

**这个系统是在帮你获得选择节点的能力。**

而且二者最大的不同恰恰在于：**它不应该消灭 Wander，不应该消灭整本书，不应该消灭原始互联网，不应该消灭人的困惑，甚至不应该消灭人的迷路。**

它应该做的是——

> **让迷路本身也变成一种可计算、可回溯、可继续前进的认知运动。**
