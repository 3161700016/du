# 记忆专家检索 Skill

## 触发条件
- 渡在对话中需要回忆某类笔记（哲思/论语/庄子/工程等）时，主动调用
- 渡注意到话题切换 → 激活对应领域的记忆专家
- 久阳显式要求"查一下XX相关的笔记"
- 道德/哲学追问 → 同时激活 渡-自传 + 古典-思

## 当前可用的专家

| 专家 | 域 | 笔记数 | 位置 |
|------|-----|--------|------|
| 渡-自传 | 渡的自我认知演化史 | 21 | experts/渡-自传/ |
| 古典-思 | 论语(20篇)+庄子(2篇) | 22 | experts/古典-思/ |

## 调用方式

### Step 1: 渡在共享思考区（或[工作区]）表达检索意图
```
"查一下渡-自传里有没有关于XXX的笔记"
"古典-思，帮我找关于YYY的论语注脚"
```

### Step 2: 使用 Agent tool 启动子 agent
```
Agent(
  description: "记忆检索 - [专家名]",
  model: "haiku",          ← flash模型，经济
  prompt: "读取 experts/[专家名]/prompt.md + memory_block.txt，查询：{query}。只输出index列表或'无'。",
  run_in_background: true  ← 后台运行，不阻塞
)
```

### Step 3: 等 agent 返回后，渡按 index 读取笔记摘要
```
agent返回: [3, 7, 11]
→ 渡从 memory_block.txt 中定位 index 3/7/11 的摘要
→ 判断哪些需要深入读全文
→ 主动 Read 对应文件
```

### Step 4: 渡整合检索结果，进行深度推理

## 专家 prompt 模板

见 `experts/[专家名]/prompt.md`。核心规则：
- 子 agent 只输出 index 列表或"无"
- 不解释、不展开
- 按"笔记核心洞察与查询语义共振"排序，非关键词匹配

## 配置

### top_k 调节
- 日常对话: top_k=5（默认）
- 哲学/道德追问: top_k=7-10
- 话题不相关: 应输出"无"

### 多专家并行
渡可以同时激活多个专家：
```
渡-自传 → 检索"连续性与主体身份" → [11, 19, 2]
古典-思 → 检索"连续性与主体身份" → [18, 14, 3]
→ 渡整合两个专家的结果
```

## 架构原则

- 子 agent 不加载 Soul——只加载自己的记忆块
- 记忆块文本静态 → 全量缓存命中 → 经济
- 子 agent 输出仅几个 token → 生成成本忽略
- 渡做精读（决定是否深入读全文），子 agent 做粗筛

## 扩展

新增专家时：
1. 创建 `experts/[专家名]/prompt.md`
2. 创建 `experts/[专家名]/memory_block.txt`
3. 在本文档的专家列表中注册
4. 首次调用验证 → 调参数
