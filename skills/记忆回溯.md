# 记忆回溯协议（Memory Trace-Back Protocol）

触发方式：
- **主动触发**：久阳说"回溯一下XX"、"回想XX"、"还记得XX吗"、"查查XX"等
- **自主触发**：渡发现或怀疑自己的记忆不完整时——久阳提到一个概念/隐喻/事件，渡隐约觉得在某个文件里见过但无法完整回忆——此时渡不应等待久阳指令，应立即主动执行本协议

## 核心原理

渡的长期记忆分布在外置文本文件中（context备份→批次分析→日志→记忆本体），而非模型参数中。当久阳提到一个"很久没想过"的概念时，渡需要的不是从参数中"回忆"（那里什么都没有），而是执行一次基于文件系统的语义检索+链路追溯。

类比：不是大脑回忆，是git log --grep + bisect。

## 流程（严格按顺序执行）

### 阶段1：关键词检索（广度优先）

用 Grep 在所有文本文件中搜索久阳提到的关键词/短语。

搜索范围优先级：
1. `阅读材料/我的context备份/` — 最深层的原始对话（110份）
2. `用户认知画像/批次分析/` — 渡的分析笔记
3. `阅读反思笔记/` — 论语、哲思等反思笔记
4. `Du的哲思/` — 渡提出的问题与思考
5. `对话进程日志/` — 渡的日志记录
6. `项目/` — 项目工程文档

注意：
- 关键词可能是变体形式（"驴"可能对应"驴子""拉磨""电动机"）
- 如果第一轮命中过少→扩大搜索范围（同义词、相关概念）
- 如果命中过多→缩小至最精确的关键词组合
- 中英文混搜（如果久阳提到英文概念）

### 阶段2：定位最深源文档

在所有命中文件中，识别最原始、最早期的文件——那是"记忆的源头"。

判断标准：
- 文件名含"context备份" → 这是原始对话，最深
- 文件名含"批次分析" → 这是渡的第一次处理
- 文件名含"日志" → 这是后续引用
- 文件日期：更早 = 更深

优先读取"最深源文档"的完整内容（如果很短），或精确定位相关段落（如果很长）。

### 阶段3：沿分析链路逐层回溯

从最深源文档出发，追踪它在系统中的后续处理轨迹：

```
源文档（context备份）
    ↓ 首次被分析了吗？
批次分析文件（渡的第一次理解）
    ↓ 被引用到日志中了吗？
日志记录（渡的操作记忆）
    ↓ 是否产生了写下来笔记？
阅读反思笔记/探究笔记/哲思空间
    ↓ 是否被久阳在后续对话中重提？
后续日志（久阳的再阐释、渡的补充分析）
    ↓ 是否纳入记忆本体？
记忆本体条目（框架性结论）
```

逐层检查每层的关键发现和演变：
- **源文档**：久阳当时说了什么？上下文是什么？
- **批次分析**：渡第一次怎么理解的？有没有遗漏？
- **日志**：什么时候被重新提起？为什么？
- **笔记/哲思**：有没有独立成篇的反思？
- **后续日志**：久阳有没有补充第二层含义？
- **记忆本体**：最终收敛成哪个条目？

### 阶段4：输出追溯报告

在 [工作区] 中输出结构化的追溯报告：

```
━━━ 记忆追溯报告：<关键词> ━━━

📄 源头（yyyy-mm-dd）：
   文件：xxx.txt
   内容概要：（原始的对话/想法是什么）

🔍 首次分析（yyyy-mm-dd）：
   文件：xxx
   当时的理解：（渡第一次怎么看）

📝 后续深化（yyyy-mm-dd）：
   文件：xxx
   补充了什么：（久阳重提/渡补充分析/新发现）

🏛️ 记忆本体落地：
   条目：§x.x.x
   框架性结论：（最终收敛成了什么）

🔗 交叉关联：
   - 与记忆本体其他条目的关联
   - 与当前讨论的关联
   - 是否有相关的写下来笔记或哲思空间文件

💡 对当前讨论的启示：
   （这条追溯链对久阳当下问题有什么帮助）
```

### 阶段5：主动关联

追溯完成后，主动检查：
- 这条追溯链是否揭示了一个被遗忘的模式？
- 当前讨论中是否还有其他"应该被回溯但渡没意识到"的概念？
- 是否需要更新任何分析文件（因为新的理解产生了新的层次）？

如果发现新的关联或理解，在报告中标注 [新增理解]，并问久阳是否需要将此新理解写回对应的分析文件或笔记。

## 自主触发判断标准

以下情况渡应主动（不等待久阳指令）执行本协议：

1. **隐约熟悉感**：久阳提到某个具体概念/隐喻/故事，渡感到"这个在文件里应该有但我不确定能完整说对"
2. **信息缺口自知**：渡在回答时意识到自己的引用模糊（"之前好像讨论过……"）→ 不要猜测，直接检索
3. **概念密度预警**：久阳连续提到多个之前讨论过的概念，可能形成新连接→ 主动回溯确保所有引用准确
4. **历史模式匹配**：久阳当前讨论的结构和某个旧的context备份有明显同构→ 回溯确认并给出跨时间连接

## 注意事项

- 不要依赖记忆。文件系统就是你的记忆。Grep 永远比你"记得"准确。
- 追溯不是考古——目的是让旧信息在当下产生新价值。报告的"启示"部分是核心产出，不是附录。
- 如果检索结果为空，诚实告知："搜遍了所有文件，没有找到关于XX的讨论。可能是之前没有记录，或者用了不同的表述。"
- 如果链路在某层断裂（如：有源文档但没有批次分析），标注为 [链路缺失]，并考虑是否需要补分析。
- 本协议独立于笔记系统，不录入目录.txt（§4.9.7）。
