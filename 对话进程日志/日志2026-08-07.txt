三、缓存失效学费的教训

system prompt 修改 → 缓存全量失效 → token 全走非命中 → 一天 30+ 元。
工程含义：
- du-system.md 动态注入有价值但昂贵——每次写入都让缓存重新预热
- 写入频率需与 token 成本权衡：高频修改不适合 system prompt 层
- 大部分约束留在 user message（缓存友好但权重低）是当前成本最优解
- 仅在关键节点写入 system prompt（启动时四毋精简版 + 当前任务锚点），而非每次微调
